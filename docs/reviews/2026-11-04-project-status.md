# 파일 트리에 프로젝트별 상태 표시 (시안)

요청: 파일 트리의 프로젝트마다 상태를 보여서, 지금 어느 프로젝트에 개입해야 하는지 바로 알 수 있게 한다.
시안은 디자인 캔버스(아티팩트)로 만들었다. A안 점과 칩, B안 세션 줄, C안 위에 "지금 볼 것" 모음, 그리고 상태·우선순위 범례.
리뷰어는 아티팩트를 열 수 없어서, 같은 원본을 저장소 밖 `review-artifacts/project-status/`에 두고 봤다.

## 시안 리뷰 1차 (v5)

### R1 · P2 · 자동 깨우기 멈춤이 상태 분류에 없음 — 타당

- 근거:
  - `chat.rs`의 `paused()`가 깨우기 제한에 닿은 작업그룹을 돌려준다.
  - 채팅 패널(`ChatPanel.tsx`의 `chat-paused`)에는 재개 버튼이 있고, 폰(`MobileApp.tsx`)은 프로젝트 목록에 이미 `pausedBadge`를 보인다.
  - `unread()`는 사용자에게 온 메시지만 센다. 그래서 세션끼리만 주고받다 멈추면 A·C안 어디에도 드러나지 않는다.
- 수정: "재개 필요" 칩(주황 테두리, 글자)을 넣었다. 응답 대기(칠한 칩)와 모양을 다르게 했다.
  - 우선순위는 응답 대기 다음, 오류 앞(2번)이다.
  - A·B·C안 모두에 예를 넣었다(notes 프로젝트).
  - 범례에는 데이터를 어디서 가져오는지(`chat_paused`) 적었다.

### R2 · P2 · 작업·완료 점이 색에만 기대고 깜빡임이 거의 사라짐 — 타당

- 근거: 흐려짐이 가장 깊을 때(opacity .25) 활성 행 배경과의 대비를 계산하면 약 1.5:1이다. opacity를 .5까지만 낮춰도 약 2.3:1로, 그래픽 요소 기준 3:1에 못 미친다.
  - 빈 span에는 상태를 설명하는 이름이 없었다.
- 수정:
  - 작업 중은 속이 빈 파란 고리로 바꿨다. 움직임은 크기만 바뀌고 흐려지지 않는다(대비 약 4.8:1 유지). 움직임 줄이기 설정이면 멈춘다.
  - 완료는 꽉 찬 초록 점이다(약 4.6:1).
  - 대기·재개·오류는 글자 칩이다.
  - 프로젝트 줄의 툴팁과 스크린리더 이름은 "ddak — 작업 중 1 · 완료 1"처럼 상태별 세션 수로 정했다.

### 데이터와 결정 확인 — 모두 반영

- Windows의 화면 읽기와 훅은 작업 중, 또는 상태 없음만 준다. 그래서 완료와 오류는 프로그램이 실제로 보낸 신호가 있을 때만 그린다.
  - 범례 7번은 "쉬는 중·신호 없음"으로, 작업 중이 사라졌다고 완료로 짐작하지 않는다는 줄을 넣었다.
- C안 요약은 상태 설명(msg)이 있을 때만 쓴다. 없으면 상태 이름으로 대신한다. 예는 "오류 (설명 없음)"이다.
- 완료 점을 언제 지울지는 범례에 "미정"으로 바꿨다. 보고 있는 프로젝트에서 끝난 경우와 여러 세션 가운데 일부만 본 경우도 결정 대상으로 남겼다.

### 화면 (Sidebar ProjectNode)

- 가장 급한 것 하나: 응답 대기 > 재개 필요 > 오류 > 작업 중 > 완료.

  - 완료는 꽉 찬 점이다.
  - 대기·재개·오류도 같은 색 점을 둔다.
- 글자 칩(가장 급한 것만):
  - 응답 대기: 칠한 칩 "waiting N"(`--status-awaiting-bg/fg`).
  - 재개 필요: 테두리 칩(`--status-awaiting-bg` 색).
  - 오류: `--error` 글자.
  - 안 읽은 배지는 지금 그대로 따로 둔다.
- 점 테두리는 줄 바탕과 같은 색이다(`--sidebar-bg`, 활성 `--row-active`, 마우스 `--hover`). 새 색 토큰은 만들지 않는다.
- 상태 이름:
  - 줄 툴팁은 지금 경로 아래에 "waiting 1 · working 2"처럼 상태별 수를 붙인다.
  - 프로젝트 줄은 포커스를 받는다(tabIndex=0). aria-label은 이름, 작업그룹, 상태 요약, 안 읽은 수를 담는다.
    Enter·Space로 옮겨 가고, :focus-visible이면 윤곽선을 그린다(계획 리뷰 R3).
    처음 계획한 sr-only 글자는 aria-label이 줄 안의 글자를 대신 읽히게 하므로 쓰지 않는다.
  - 파일 트리 방향키 탐색은 이번 범위 밖이다.
- 문구: `sidebar.statusAwaiting`·`sidebar.statusPaused`·`sidebar.statusSummary` 등을 en·ko에 넣는다. 상태 이름은 `status.*`을 다시 쓴다.

## 코드 리뷰 1차

### R4 · P2 · 역할 없는 div에 붙인 aria-label — 타당, 수정

- 근거: 프로젝트 줄은 tabIndex와 aria-label만 있는 div였다.
  - ARIA 1.2는 generic 역할에 이름 붙이기를 금지한다. 그래서 작업 중·완료처럼 글자 없이 점만 있는 상태는 이름이 전달된다는 보장이 없다.
  - 시험은 속성이 있는지만 봤다.
- 수정:
  - 프로젝트 고르기를 줄 안의 `<button type="button" class="project-select">`로 바꿨다. 아이콘·이름·칩·배지·작업그룹이 그 안에 들어간다.
    - aria-label을 이 버튼에 두고, 보고 있는 프로젝트에는 `aria-current="true"`를 붙인다.
    - 없는 폴더에는 `aria-disabled`를 붙인다. disabled는 오른쪽 클릭 메뉴까지 막을 수 있어서 쓰지 않는다.
  - 화살표·+·×는 버튼 밖에 둬서 그 조작의 의미를 가리지 않는다.
  - 줄의 tabIndex·키 처리는 지웠다. Enter·Space는 버튼의 기본 동작이고, 누르면 줄의 onClick으로 올라간다.
  - 버튼 안으로는 줄의 취소선이 이어지지 않아, 없는 폴더의 이름에 따로 취소선을 넣었다.
- 시험:
  - `projectStatus`: 고르기가 포커스를 받는 button이고, 이름이 버튼에 있으며 줄에는 없고, aria-current가 있는지 본다.
  - `projects`: 버튼에 포커스를 두고 누르면 그 프로젝트로 가는지 본다.
  - 합성 키 이벤트로는 버튼이 눌리지 않아서 Enter 자체는 시험하지 못한다. 진짜 버튼의 기본 동작에 맡긴다.
  - 실제 스크린리더에서 어떻게 읽히는지는 확인하지 못했다.

### R5 · P2 · 탭을 다시 띄운 뒤 옛 상태가 남음 — 타당, 수정

- 근거: `relaunchTabs`는 `runs`만 올리고 `statuses`·`waking`을 비우지 않는다. 새 Terminal은 상태가 바뀌기 전에는 알리지 않는다.
  - 이 문제는 이번 변경 전부터 창 이름표에 있었다. 이번 변경으로 사이드바에도 드러났다.
- 수정: 다시 띄울 탭들의 창의 `statuses`·`waking`을 ↻와 같이 지운다. 늦게 불려도 지금 탭 배치를 쓰도록 `latest.current.tabs`를 쓴다.
- 시험: `projectStatus`의 두 번째 탭을 기다림으로 만든 뒤 `devHooks.relaunchActiveTab()`을 부른다. 옛 기다림이 빠지고 첫 창의 오류만 남는지 본다.
  - 수정을 끄면 "waiting 1 · error 1"이 남아 실패했다.

### 질문: 최소 너비 160px에서 이름이 남나 — 확인해 보니 문제, 수정

- 실험: 160px에서 기다림 칩과 안 읽은 배지가 함께 있으면 이름 너비가 0이었다. 멈춤 칩("resume needed")과 함께여도 0이었다. 줄이 넘치지는 않았다.
- 수정:
  - 칩이 이름보다 먼저 줄어든다(`flex-shrink: 20`, 말줄임, 최소 18px).
  - 이름은 최소 32px을 남긴다(`.project-select .tree-name`).
- 시험: `projectStatus`에서 사이드바를 160px로 줄여 두 경우를 본다. 이름이 24px 이상이고 줄이 넘치지 않으면 통과다.
  - 수정 전에는 이름이 0으로 실패했고, 수정 뒤에는 32px로 통과했다.
- 고친 뒤 전체 자체 테스트 (Windows, main): 기준 코드와 실패 목록을 비교했고 새로 생긴 실패는 없다. 새 확인 15개는 모두 통과했다.

## 코드 재리뷰 1차

- R4·R5는 해소됐다. 160px 질문도 해소됐다.

### R6 · P2 · 창 닫기 시험이 상태 없는 창을 닫음 (새 범위, 수정으로 생긴 시험 회귀) — 타당, 수정

- 근거: R5 시험을 넣으면서 두 번째 탭을 다시 띄운 뒤 상태 없는 새 터미널을 닫게 됐다. 그래서 "닫은 창도 세는" 결함이 있어도 통과했다.
- 수정: 다시 띄운 터미널에 working을 보낸다. "error 1 · working 1"이 될 때까지 기다린 뒤 닫고, "error 1"만 남는지 본다.
- 확인:
  - 고친 시험은 통과한다.
  - 남은 창만 세기를 끄면(`Object.values(statuses)`) "error 1 · working 1"이 남아 실패한다. "지우면 표시 없음"도 함께 실패한다.
