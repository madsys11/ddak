# 리뷰 대응: 채팅방 1단계 (2026-10-24)

리뷰 범위: `9933a0e` 이후 커밋 전 작업 트리 (`chat.rs`, `pty.rs` 참여, 기본 설정). 지적 다섯 건(P1 1, P2 4).
모두 소스로 확인했고 타당해서 고쳤다. 테스트마다 수정을 잠시 끄고 실패하는 것을 확인했다.

## 1. [P1] 끊긴 줄 뒤에 붙인 메시지가 다시 켜면 사라짐 — 타당, 수정

**검증**: 소스.
- 붙이기는 마지막 줄을 보지 않았다. 줄바꿈 없이 끊긴 JSON 뒤에 새 줄이 이어 붙어 한 줄로 깨졌다.
- 읽기는 `lines().map_while(Result::ok)`라서, UTF-8이 깨진 줄에서 읽기를 멈추고 그 뒤의 정상 줄을 버렸다.

**수정**
- 읽기: 파일을 바이트로 읽고 줄바꿈으로 나눈다. 줄마다 UTF-8·JSON을 따로 읽어 깨진 줄만 건너뛴다.
- 붙이기: 파일 끝 바이트가 줄바꿈이 아니면 줄을 바꾼 뒤 붙인다.
- 번호는 가장 큰 번호 + 1.

**확인**: Rust `broken_lines_lose_nothing_after_them`. 정상, UTF-8 깨짐, 정상, 끊긴 줄 순서로 둔 파일에서 정상 두 개를 읽고,
새 메시지를 붙인 뒤 다시 읽어도 셋이 다 있다. 줄바꿈 넣기를 끄거나 UTF-8 줄 단위 읽기를 끄면 실패.

## 2. [P2] 읽기 실패를 빈 방으로 봐서 번호가 겹침 — 타당, 수정

**수정**: 파일 없음만 빈 방이다. 그 밖의 읽기 실패는 오류이고, 그 방은 읽기(`chat_messages`, `read_messages`)와
쓰기(`post`) 모두 오류를 낸다. 실패는 기억하지 않아서 고치면 다음에 다시 읽는다.

**확인**: Rust `unreadable_room_refuses_reads_and_writes`. 쓰기만 되는 권한(0200)에서 읽기·쓰기 모두 오류이고 파일이
그대로다. 권한을 돌리면 3번으로 이어 쓴다. 구분을 끄면 실패.

## 3. [P2] 같은 키로 다시 들어와도 이름이 바뀜 — 타당, 수정

**수정**: 키 → 이름을 프로젝트마다 `<slug>.names.json`에 둔다 (참여 수명과 따로).
- 그 키의 참여자가 모두 나가도, 앱을 다시 켜도 같은 이름이다. 창의 세션 ID는 복원 때도 같다.
- 정해 둔 이름은 다른 키에 주지 않는다.
- 이름 파일을 읽지 못하면 (없음 말고) 이번 실행에서는 메모리에만 두고 파일을 덮어쓰지 않는다.

**확인**: Rust `name_stays_with_key`. dev와 dev-2가 모두 나간 뒤 두 번째 키는 다시 dev-2를 받고, 새 키는 dev-3을 받는다.
다시 켜도 같다. 지금 접속자만 보던 이전 방식으로 되돌리면 실패. 처음에는 조회만 껐더니, 겹침 검사가 매핑을 봐서
테스트가 통과했다. 겹침 검사까지 되돌려 다시 확인했다.

## 4. [P2] 설정이 허용한 이름을 멘션하지 못함 — 타당, 수정

**판단**: 이름을 멘션용으로 바꾸면(공백을 `-`로) 표시 이름과 멘션 이름이 달라져 헷갈린다. 그래서 멘션을 이름에 맞췄다.

**수정**: `@` 바로 뒤에 오는 지금 참여자 이름(과 `all`) 중 가장 긴 것을 멘션으로 본다. 그 뒤는 끝·공백·문장부호여야
한다. 공백으로 나누지 않으므로 `origin/코드 리뷰`, `origin/reviewer.`도 맞고, `origin/dev-2`가 `origin/dev`로 잘못 잡히지
않는다.

**확인**: Rust `mentions_match_whole_names`. 이전 방식(공백으로 나누고 끝 문장부호를 자름)으로 되돌리면 실패.

## 5. [P2] Origin을 검사하지 않음 — 타당, 수정

**검증**: MCP 규격(streamable HTTP)은 서버가 Origin을 검사하라고 한다.

**수정**: Origin이 있으면 이 서버 자신(`http://127.0.0.1:<포트>`, `http://localhost:<포트>`)일 때만 받고, 아니면 403이다.
CLI는 Origin을 보내지 않으므로 없으면 받는다.

**확인**: Rust `mcp_over_http`. `Origin: https://untrusted.example`은 토큰이 맞아도 403이고 메시지가 남지 않는다. 자기
Origin은 200이다. 검사를 끄면 실패.

## 그 밖

- 리뷰어 의견:
  - 토큰 노출과 읽은 위치를 메모리에 두는 정책은 받아들일 만하다고 했다.
  - 터미널을 다시 띄울 때도 읽은 위치가 처음으로 돌아간다는 점은 스펙에 적었다.
  - 저장된 탭은 저장할 때의 인자를 쓰므로, 설정을 고쳐도 새 작업그룹이나 새로 추가한 세션부터 적용된다. 이것도 스펙에
    적었다.
- 리뷰어 환경에서는 포트를 열 수 없어 서버를 띄우는 테스트 세 개가 실패했다. 저장·참여 테스트는 서버 없이 만들어
  (`Chats::new`) 포트 없이 돌게 했다. HTTP 테스트(`mcp_over_http`)만 포트를 연다.

## 후속 리뷰: P2 두 건 — 모두 타당, 수정

### [P2] 깨진 이름 파일을 빈 매핑으로 보고 덮어씀

**검증**: 소스. 이름 파일을 읽은 뒤 JSON이 아니면 `unwrap_or_default()`로 빈 매핑을 만들면서 `saved: true`로 뒀다. 그래서
다음 참여 때 파일을 덮어썼다.

**수정**: JSON으로 읽지 못해도 읽기 실패와 같이 본다. 그 실행에서는 메모리에만 두고 파일을 덮어쓰지 않는다.

**확인**: Rust `name_stays_with_key`. 이름 파일의 마지막 바이트를 자르고 새 키로 참여해도 파일이 그대로다. 되돌리면 실패.

### [P2] 이름 안의 @all을 따로 멘션으로 봄

**검증**: 소스. 모든 `@` 위치를 따로 보느라, 맞춘 이름 안의 `@`도 다시 검사했다.

**수정**: 이름을 맞추면 그 이름이 차지한 곳 뒤부터 다음 `@`를 찾는다.

**확인**: Rust `mentions_match_whole_names`. `origin/코드 @all 리뷰`만 멘션하면 그 이름 하나만 나온다. 건너뛰기를 끄면 실패.
