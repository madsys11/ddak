# Finder에서 끌어 놓은 파일의 경로 넣기 (2026-10-27)

**요청** (사용자, 터미널에서): 앞 수정(0bb47d8, `2026-10-27-drop-navigation.md`)을 설치한 뒤 "놓을 수 없는 게 아니라 경로가
들어가야 하는 거 아냐?". iTerm·터미널 앱처럼 Finder 파일을 터미널·채팅 입력란에 놓으면 경로가 들어가게 한다.

**방법 고르기**:
- 웹뷰의 drop은 File(이름·내용)만 주고 경로는 주지 않는다.
- Tauri의 파일 끌어 놓기(`dragDropEnabled: true`)는 경로를 주지만 처리기가 늘 true를 돌려 모든 끌기를 가로챈다
  (tauri-runtime-wry `with_drag_drop_handler`, wry `drag_drop.rs`). 파일 트리 → 터미널 끌기(HTML 끌어 놓기)가 죽어서,
  트리 끌기를 마우스 이벤트로 다시 만들어야 한다.
- 고른 것: 웹뷰 끌어 놓기는 그대로 두고, drop 때 Rust가 macOS 끌기 대지(`NSPasteboardNameDrag`)에서 파일 주소를 읽는다.
  대지는 놓은 뒤에도 마지막 끌기를 들고 있으니, 놓은 File 이름이 모두 그 경로들에 있을 때만 쓴다 (다른 끌기의 대지면 넣지
  않음). 폴더는 File로 오지 않을 수 있어 경로 쪽이 더 많아도 된다.

**구현**:
- `fs.rs` `drag_files`: 대지 항목의 `public.file-url` → NSURL `filePathURL`(Finder의 파일 참조 주소 `file:///.file/id=…`도
  경로로) → 경로를 NFC로. NSURL 경로는 한글을 풀어 쓴 꼴(NFD)이라 터미널에서 자모가 흩어진다. APFS는 둘 다 찾는다.
  `selftest_drag_files`(DDAK_SELFTEST에서만): 시스템 대지 대신 이름 붙인 대지에, 있는 파일은 Finder처럼 파일 참조 주소로 싣는다.
- `dragPath.ts`: `isFileDrag`, `droppedFiles`(이름은 drop 처리 중에 바로 읽고 Rust에 묻는다. 비교는 NFC).
  `refuseOutsideDrops`는 받는 쪽이 처리하지 않은 앱 밖 파일만 막는다 (전과 같음).
- `Terminal.tsx`: 감싼 절대 경로들을 공백으로 붙여넣기 (트리 끌기와 같은 `paste`). `ChatPanel.tsx`: 절대 경로들을 커서 자리에.

**확인**:
- Rust `reads_dragged_file_paths_from_pasteboard`: 따로 만든 대지에 파일 참조 주소로 싣고(실렸는지 `file:///.file/id=` 확인)
  읽으면 원래 경로 (한글·공백 이름, 폴더, 없는 파일). NFC로 바꾸기 전에는 이 테스트가 실패했다 (NFD). Rust 119개 통과.
- 자체 테스트 `trashDrag`:
  - "Finder에서 놓은 파일은 터미널에 감싼 절대 경로, 채팅 입력란에 절대 경로 (여러 개, 한글·공백 이름)".
  - "놓은 이름과 끌기 대지가 다르면 넣지 않고, 터미널·채팅 입력란 밖에는 받지 않음".
  - 수정을 끄고 확인: 터미널의 앱 밖 파일 처리를 빼면 첫째 실패, 이름 대조를 빼면 둘째 실패.
- 앞 수정의 검사 바로잡기: 합성 DataTransfer는 dropEffect를 바꿔도 남지 않아 늘 none이다 (터미널이 copy로 두어도 none으로
  읽힘). 그래서 앞 검사의 "dropEffect가 none"은 아무것도 확인하지 않았다. 이번에는 기본 동작을 막았는지만 본다.
- 실제 Finder 끌기는 맥 앞에서 확인해야 한다 (합성 이벤트는 WebKit이 실제 끌기에서 File을 어떻게 주는지, 특히 폴더를
  확인하지 못한다).
- 전체 `selftest.sh`: 모든 시나리오 통과 (main 456개 PASS, 실패 없음. 앞 수정 때 가끔 실패하던 작업그룹 끝내기도 이번엔 통과).

## 리뷰 1차 (#216)

**R1 [P2] 이름 부분집합 대조로는 다른 끌기의 대지를 거르지 못함 — 타당.** 놓은 이름이 대지 이름에 "들어 있기"만 보면 대지에
더 있는 파일까지 넣고, 같은 이름 File 둘도 대지의 하나로 통과한다 (Set). 이름이 같은 다른 끌기도 못 거른다.
수정: 두 가지를 함께 본다.
- 끌기 대지 번호: 받는 쪽의 dragover 때 `drag_count`(NSPasteboard `changeCount`, 새 끌기마다 바뀜)를 묻어 두고
  (`noteFileDrag`, 묻는 중이면 그 답을 기다림), drop 때 `drag_files`가 돌려준 번호와 같아야 한다. dragover는 끌기가 이어지는
  동안 오므로 그때의 대지는 이 끌기의 것이다.
- 이름은 개수까지 똑같아야 한다 (정렬한 목록 비교, NFC).
폴더: WebKit이 실제 Finder 끌기에서 폴더를 File로 주지 않으면 이름이 맞지 않아 아무것도 넣지 않는다 (틀린 경로보다 안전).
실제 Finder에서 폴더 단독·섞어 놓기를 확인해야 한다.
확인: "끌기 대지가 이 끌기의 것이 아니면(이름 다름·더 있음·수 다름·끌기 중 바뀜) 넣지 않고…" (이름이 같은 새 끌기는
dragover 뒤 대지를 다시 실어 시험). Rust 테스트에 다시 실으면 번호가 바뀌는지 추가.

**R2 [P2] 경로를 묻는 동안 채팅 초안을 고치면 고친 글이 지워짐 — 타당.** 놓을 때의 선택 범위로 늦게 자르기 때문이다.
수정: 초안이 바뀔 때마다 올리는 번호(`draftRev`, `[draft]` 효과)를 놓을 때 기억하고, 응답 때 다르면(입력, 보내기로 비움, 다른
놓기) 넣지도 포커스를 옮기지도 않는다. 입력란이 화면에서 빠졌어도 넣지 않는다.
확인: "경로를 묻는 동안 채팅 초안을 고치면 경로를 넣지 않고 고친 글을 그대로 둠" (abcd, 선택 1..3, drop 직후 NEW TEXT).

수정을 끄고 확인 (번호 대조·개수 대조·초안 번호를 뺌): 두 검사 실패. 결과는 리뷰의 재현과 같다 (대지에 더 있음·같은 이름
둘·끌기 중 바뀜이 모두 들어감, 고친 초안이 `N/…/b.txt  TEXT`). Rust 119개 통과, `trashDrag` 통과.

## 재리뷰 1회 (#218)

**R1 남음 — 타당.** dragover에서 부른 `drag_count`도 비동기라, Rust에서 늦게 실행되면 다음 끌기 B의 번호를 읽고, drop의
`drag_files`도 B를 읽으면 번호·이름이 같아 B의 경로를 넣는다. 실제로는 놓은 뒤 새 끌기를 시작하기 전까지 IPC가 밀려야
하지만, 순서상 막을 수 있다.
수정: 놓을 때 이미 받아 둔 번호만 쓴다 (`seenCount`는 응답이 왔을 때만 바뀌고, drop 때 그 값을 바로 읽는다. 없으면 넣지
않음). 받아 둔 답은 놓기 전에 Rust에서 읽힌 것이고, 그 dragover 뒤이므로 이 끌기 중의 대지 번호다. 놓은 뒤 읽은 번호와
같으면 그 사이 새 끌기가 없었다. 실제 끌기는 dragover가 여러 번 오고 IPC는 1ms 안팎이라 놓기 전에 답이 와 있다.
확인: 같은 검사에 "끌기 중 번호를 받기 전" 경우 추가 (대지를 다시 실은 뒤 dragover 바로 다음에 drop). 놓을 때 번호를
새로 읽게 바꾸면 이 경우와 "끌기 중 바뀜"이 들어가 실패.

**R2 남음 — 타당.** `draftRev`를 `[draft]` 효과에서 올려서, 보내기 응답의 비우기와 drop 응답이 렌더 전에 한 배치로 오면
번호가 같아 비운 초안 뒤에 삽입이 적용된다.
수정: 두 겹.
- 초안을 바꾸는 곳(입력, 보내기 비우기, 멘션, 놓기)은 모두 `setDraft`를 거치고, 거기서 바로 번호를 올린다 (효과 아님).
- 삽입 갱신은 `insertAt(before, start, end, text)`: 적용할 때 초안이 놓을 때의 글(before)과 같을 때만 바꾼다.
확인: "채팅 초안 비우기와 늦은 삽입이 한 번에 적용돼도 비운 초안에 넣지 않음" (ChatPanel이 쓰는 두 갱신 함수를 그 순서로
적용. 그대로면 넣음도). `insertAt`의 비교를 빼면 실패. 앱 안에서 React 배치 순서를 일부러 만드는 검사는 아니다.

`trashDrag` 6개 통과, tsc 통과. Rust는 바뀌지 않음 (119개).

## 설치 후 실제 Finder 확인 (7bb9412)

사용자가 설치한 앱에서 Finder 항목을 끌어 놓아 확인했다. 모두 경로가 들어갔다.
- 터미널: 그림 파일, 공백·`·`·한글이 섞인 이름의 파일(작은따옴표로 감쌈), 한글 이름 폴더 하나, 폴더와 그림 파일을 함께
  (두 경로가 공백으로 이어짐).
- 채팅 입력란: 폴더 하나, 그림 파일 하나 (절대 경로).
위 "남는 제한"의 폴더 걱정은 해당 없다: WebKit은 실제 Finder 끌기에서 폴더도 File로 넘겨 이름 대조를 통과한다.
