# 선택 창 질문: 화면 위로 넘어가면 스크롤 기록에서 이어 읽기 (2026-10-28)

**보고** (사용자, 폰 캡처): codex 업데이트 안내(`Update available · 0.164.0 → 0.165.0`, 선택지 셋)가 폰에서 "질문이 화면보다
길어 맥에서 답해야 합니다"로 나와 누를 수 없었다. 앞 수정(1d16e83, codex 권한 확인의 제목 줄)을 설치한 뒤다.
사용자 질문: "질문이 화면보다 길면 스크롤 하면 되는 거 아냐?"

**원인** (채팅 기록 저장값 `realbilliards-battle` #36으로 확인): 질문은 두 줄(`Update available …`, `Release notes: …`)이다.
`readDialog`는 보이는 화면만 받아, 첫 선택지 위로 가로줄이나 빈 줄 셋을 못 찾고 화면 맨 위에 닿으면 `complete: false`로 둔다.
업데이트 안내는 codex가 화면 맨 윗줄부터 그려서 위에 경계가 없다 (codex는 대체 화면을 쓴다: 0.165 바이너리에 `no-alt-screen`,
`AltScreenMode` 문자열). 앞 수정의 제목 규칙은 권한 확인 제목과 `Press … to confirm or … to cancel` 안내에만 맞는다.
폰 문구도 틀렸다: 질문이 길어서가 아니다.

**수정**:
- `readDialog(screen, above, start)`: 화면 안에서 선택지를 찾고, 질문은 화면 위로 넘어가면 `above`(화면 위의 줄)로 이어
  올라간다. 경계를 찾거나, 경계 없이 `above`의 맨 위에 닿았는데 그곳이 터미널 내용의 처음(`start`)이면 complete.
  codex 제목 규칙은 경계가 없을 때 그대로 먼저 본다 (대체 화면에서도 대화 기록이 질문에 섞이지 않게).
- `Terminal.tsx` `dialogNow` (알리기·답 넣기 직전 확인·커서 확인 모두 같은 것):
  - 대체 화면: 기록이 없고 프로그램이 화면 전체를 그리므로 맨 윗줄이 처음 (`start` true, `above` 없음).
  - 일반 화면(claude 등): 화면 위 스크롤 기록을 최대 500줄(`ABOVE_MAX`) `above`로. 기록을 다 넘겼고(`baseY` ≤ 500) 기록 한도로
    버려진 줄이 없을 때(`buffer.length < rows + scrollback`)만 처음.
- 문구: `prompt.incomplete` "질문 전체를 읽지 못해 맥에서 답해야 합니다" / "Could not read the whole question. Answer on the Mac."

**판단**:
- 대체 화면의 맨 윗줄을 처음으로 보는 근거: 대체 화면에는 스크롤 기록이 없어 그 위에 터미널 내용이 없다. 프로그램이 스스로
  위를 잘라 그리는 경우는 남는다. codex는 넘치면 아래를 `[… N lines]`로 줄이고 머리는 위부터 그린다 (앞 수정의 근거). claude는
  일반 화면을 쓴다.
- 일반 화면의 기록에는 다시 그리기 전의 낡은 화면이 남을 수 있다. 위로 이어 읽으면 질문이 더 길어질 수는 있어도 빠지지는
  않는다. 답을 넣을 때는 알린 것과 지금 읽은 것이 같아야 하므로 (`sameDialog`), 기록이 달라졌으면 넣지 않는다.

**확인**:
- `programStatusUnit` 새 검사: 위의 줄에 가로줄이 있으면 complete, 없고 처음이 아니면 아님, 처음이면 complete, 업데이트 안내
  모양은 대체 화면(처음)에서 complete·아니면 아님, 선택지는 화면 안에서만 찾음.
- `addSession`(testChatPrompt)에 실제 터미널 검사: picker에 두 선택 창을 더했다.
  - 60줄 질문: 가로줄과 앞 줄들이 스크롤 기록으로 넘어감 → 60줄 모두 읽고 채팅에서 답함.
  - 대체 화면 맨 윗줄부터 그린 짧은 질문 (업데이트 안내 모양) → 채팅에서 답함.
- 수정을 끄고 (Terminal은 화면만, readDialog는 처음을 complete로 안 봄): 두 검사 실패 (긴 질문은 43줄만 읽고 incomplete).
- 전체 `selftest.sh`: 다섯 시나리오 모두 통과 (PASS 491, 197초). tsc 통과.

## 리뷰 1차 (reviewer-2 #339)

**R1 [P2] 대체 화면의 맨 윗줄이 질문의 시작이라는 보장이 없음 — 타당.** 대체 화면에도 화면보다 긴 출력은 위가 기록 없이 사라진다
(실제 xterm에서 10줄 화면에 24줄을 쓰면 맨 윗줄이 14번째 줄). 그런데 맨 윗줄을 처음으로 봐서, 위 명령이 사라진 질문을 complete로
두고 위 명령만 다른 두 창을 같은 창으로 봤다.
수정: 대체 화면에서 위로 밀려난 줄이 있었는지 `altLost`로 따라간다 (`Terminal.tsx`). xterm `onScroll`이 대체 화면에서 밀릴 때도
울리는 것을 Node에서 확인했다 (24줄을 10줄 화면에 쓰면 14번, 스크롤 영역 안의 밀림도 울림). 화면 전체 지우기(CSI J 2·3, 맨 앞에서
J 0, `parser.registerCsiHandler`로 보고 기본 처리는 그대로)와 화면 바꾸기(`onBufferChange`)에서 처음으로 되돌린다. 밀려난 적이
없을 때만 맨 윗줄을 처음으로 본다. Node에서 들어가며 지움 → false, 짧은 출력 → false, 넘침 → true, 다시 지움 → false 확인.
확인: picker에 대체 화면에서 80줄 질문(화면보다 김)을 더했다 → 채팅에 올라오되 답할 수 없음(incomplete), 맨 위 줄이 빠져 있음.
대체 화면을 늘 처음으로 보게 되돌리면 이 검사가 실패한다 (답이 들어감).

**R2 [P2] 지금 버퍼 길이로 기록이 버려졌는지 알 수 없음 — 타당.** 한도를 넘겨 앞이 버려진 뒤 창을 넓히면 줄이 다시 감겨 길이가
줄어, 버려진 것을 처음까지 다 읽은 것으로 봤다.
수정: 일반 화면에서는 기록의 처음을 처음으로 보지 않는다 (`start` 없음). 일반 화면은 스크롤 기록에서 경계(가로줄, 빈 줄 셋)를
찾아야만 답할 수 있다. 길이로 판단하던 코드를 뺐다. 리뷰 재현(경계 없는 긴 줄 뒤의 선택 창)은 경계가 없으므로 incomplete다.
따로 검사를 더하지 않은 이유: 일반 화면에는 `start`를 주는 경로 자체가 없어졌다 (`dialogNow`). readDialog가 `start` 없이 처음에
닿으면 incomplete인 것은 단위 검사("처음이 아니면 아님")가 본다.

**알려진 한계** (일반 화면): xterm은 일반 화면에서 화면 지우기(ED 2)를 해도 그 화면을 기록으로 올리지 않는다. 그래서 지우기 전의
옛 줄이 화면 위 기록에 남아, 위로 이어 읽으면 질문에 옛 줄이 더 붙고 옛 가로줄을 경계로 쓸 수 있다. 지운 뒤 그린 것은 모두 질문에
들어가므로 빠지는 것은 없고, 위 명령이 다른 두 창은 여전히 다르다. 질문이 길게 보일 수 있을 뿐이다.

`addSession`·`programStatusUnit` 통과, tsc 통과. 전체 `selftest.sh` 다섯 시나리오 통과 (PASS 492, 195초).
