# 리뷰 대응: 작업그룹 · 터미널 입력 · 이름 바꾸기 (2026-10-23)

리뷰 범위: `7d61b29` 이후 커밋 전 작업 트리. P1 1건, P2 7건 모두 타당, 수정.

## 1. [P1] rename이 경합 중 생긴 대상 파일을 덮어씀 (`fs.rs`) — 타당, 수정

**검증**: 소스 확인. `child_path`로 대상이 없는지 본 뒤 `std::fs::rename`을 부른다. POSIX rename은 대상이 있으면
덮어쓰므로, 확인과 rename 사이에 대상이 생기면 덮어쓴다. 리뷰 쪽은 시스템 호출 경계에 경합을 주입해 실제로 확인했다.

**수정**: macOS `renamex_np(from, to, RENAME_EXCL)` (libc 0.2.191 `src/unix/bsd/apple/mod.rs`에 있음).
대상이 있으면 OS가 원자적으로 실패시킨다 (EEXIST → "exists"). 대소문자만 바꾸는 경우는 아래 8과 함께 따로 처리.

**확인**: Rust 테스트 `rename_excl_never_overwrites` — 대상이 이미 있는 상태(경합에서 진 순간과 같음)로
`rename_excl`을 부르면 AlreadyExists, 대상·원본 내용 그대로.

## 2. 기본 설정 생성이 동시에 저장된 사용자 설정을 덮어씀 (`groups.rs`) — 타당, 수정

**검증**: 소스 확인. `exists()` 확인 뒤 `fs::write`.
**수정**: `OpenOptions::create_new`로 만들고, 이미 있으면(AlreadyExists) 그대로 둔다.
**확인**: 기존 자체 테스트(파일이 없을 때 생성, 지우면 다시 생성) 통과. 경합 자체는 재현하지 않았다.

## 3. 자동 응답도 키 전송으로 쳐서 한글을 빠뜨림 (`hangul.ts`) — 타당, 수정

**검증**: xterm 소스. 터미널 질의 응답(`InputHandler.ts`의 DA 등)과 포커스 알림도 `triggerDataEvent` → `onData`로
나간다. 키 구간에 이런 응답이 오면 `xtermSent`가 켜져 다음 입력기 글자를 건너뛴다.
수정 전 코드로 자체 테스트가 실패한다 (보낸 것이 `["\u001b[0n"]`뿐, "ㅎ" 없음).

**수정**: `onData` 대신 `onKey`로 센다. `onKey`는 xterm이 키를 처리해 보낼 때만 온다
(`CoreBrowserTerminal.ts` `_keyDown` 1090행, `_keyPress` 1173행). `term.input`으로 보내는 것도 `onKey`를 일으키지 않아서
따로 거를 필요가 없어졌다.

**확인**: 자체 테스트 "한글 보정: 키 구간의 자동 응답 뒤에도 첫 자모를 보냄" (화면 밖 xterm에 붙여서 확인).

## 4. 이모지 바꾸기가 잘못된 UTF-16을 만듦 (`hangul.ts`) — 타당, 수정

**검증**: 소스 확인 (문자열 인덱스 = UTF-16 코드 단위). 수정 전 코드로 자체 테스트가 `["\ude01"]`을 보내 실패한다.
**수정**: `Array.from`으로 코드 포인트 단위로 비교·삭제 수 계산.
**확인**: 자체 테스트 "이모지 바꾸기를 코드 포인트 단위로" (😀 → 😁가 DEL + 😁).

## 5. 늦게 끝난 설정 재로드가 최신 설정을 되돌림 (`useGroups.ts`) — 타당, 수정

**검증**: 소스 확인. `alive`는 언마운트만 구분한다. 겹친 두 요청이 거꾸로 끝나면 이전 결과가 마지막에 적용된다.
**수정**: 요청마다 번호를 매기고 마지막 요청의 결과만 적용한다.
**확인**: 기존 설정 다시 읽기 자체 테스트 통과. 응답 순서 뒤집기는 재현하지 않았다 (Tauri 명령 응답 순서를 앱 안에서
조작할 수단이 없음).

## 6. 트리 갱신이 이름 입력의 선택 범위를 초기화 (`FileTree.tsx`) — 타당, 수정

**검증**: 소스 확인. 선택 효과의 의존성이 `[entry]`인데 목록을 다시 읽으면 새 객체다. 수정 전 코드로 자체 테스트가
실패한다 (커서 12-12 → 0-1).
**수정**: 입력란이 열릴 때 한 번만 선택한다 (의존성 `[]`).
**확인**: 자체 테스트 "트리가 다시 읽혀도 입력·커서 유지" (입력 중 같은 폴더에 파일을 만들어 다시 읽게 함).

## 7. 전역 Shift+Enter 매핑이 Vim 삽입 모드를 끝냄 (`Terminal.tsx`) — 타당, 수정

**검증**: ESC CR의 ESC는 Vim에서 삽입 모드를 끝내는 키다. 리뷰 쪽 실제 Vim PTY 실험 결과(i → n)와 맞다.
**수정**: Shift+Enter 변환을 세션 구성의 `shiftEnter`로 옮겼다. 기본 설정의 claude·codex 세션에만 ESC CR을 둔다.
세션이 아닌 창(⌘T, ⌘D로 연 셸)은 xterm 기본(CR)이다.
**한계**: 세션 창에서 CLI를 끝내고 같은 창에서 Vim을 열면 여전히 ESC CR이 간다.
**확인**: 자체 테스트 — 세션 창은 ESC CR, 세션이 아닌 창은 `\r`.

## 8. 대소문자 예외가 별도 하드 링크까지 허용 (`fs.rs`) — 타당, 수정

**검증**: 소스 확인. inode가 같기만 하면 허용했다. 하드 링크 `b.txt`·`link.txt`에서 `b.txt` → `link.txt`는 같은 파일로의
rename이라 아무 일도 없이 성공을 돌려준다 (POSIX).
**수정**: 대소문자만 다르고, 폴더에 그 이름 그대로인 항목이 따로 없을 때만 대소문자 변경으로 본다 (`has_entry`).
대소문자를 구분하지 않는 볼륨에서는 새 이름이 목록에 따로 없다. 그 밖에는 `RENAME_EXCL` 경로로 간다.
**확인**: Rust 테스트 `rename_checks`에 하드 링크 경우 추가 ("exists", 원본 그대로). 대소문자만 바꾸기는 그대로 통과.

## 테스트 쪽 수정

- 합성 키 이벤트는 `keyCode`가 0이라 xterm이 Enter를 알아보지 못했다. 테스트 도우미가 실제 브라우저처럼 채운다.
- 새 탭 대기 조건이 빈 배열(참)로 일찍 끝나는 경쟁 조건을 고쳤다.

## 후속 리뷰: [P1] 대소문자 변경 분기가 원자적인 rename을 우회 (`fs.rs`) — 타당, 수정

**지적**: 대소문자를 구분하는 볼륨에서 `a.txt` → `A.txt`이고 `A.txt`가 아직 없으면 "대소문자만 다르고 같은 이름 항목이
따로 없음" 조건이 참이 되어 일반 `std::fs::rename`으로 간다. 확인 뒤 `A.txt`가 생기면 덮어쓴다.
기존 테스트는 `rename_excl`을 직접 불러서 이 경로를 잡지 못했다.

**검증**: 소스 확인 (조건이 볼륨 종류와 무관하게 참). 그리고 예외 분기가 필요한지부터 실험했다 —
`rename_excl`(renamex_np RENAME_EXCL)만으로:

| 경우 | 대소문자 구분 안 함 (기본 APFS) | 대소문자 구분 APFS (디스크 이미지) |
|---|---|---|
| a.txt → A.txt, 다른 항목 없음 | 성공 | 성공 |
| b.txt → B.txt, B.txt가 따로 있음 | (같은 파일이라 해당 없음) | EEXIST, B.txt 그대로 |
| A.txt → hl.txt (하드 링크) | EEXIST | EEXIST |

**수정**: 대소문자 예외 분기와 미리 확인(`child_path`의 "있음" 검사)을 없애고 이름 검사 뒤 `rename_excl` 하나로 판단한다.
미리 확인하면 대소문자를 구분하지 않는 볼륨의 대소문자 바꾸기를 막게 되고, 예외를 두면 일반 rename으로 빠졌다.

**확인**
- 기존 `rename_checks`(대소문자만, 하드 링크, 덮어쓰지 않음)를 `fs_rename`으로 통과.
- 새 테스트 `case_sensitive_volume` (`#[ignore]`, `cargo test case_sensitive_volume -- --ignored`): 대소문자 구분 APFS
  디스크 이미지를 만들어 `fs_rename`으로 확인 — 그 이름이 따로 있으면 "exists"·내용 그대로, 없으면 대소문자 바꾸기 성공.
- 확인과 rename 사이에 대상이 생기는 경합 자체는 결정적으로 재현하지 못했다. 이제 확인 단계가 없고 OS의 원자적
  호출 하나뿐이라 그 사이가 없다.
