# Finder에서 끌어 놓으면 작업 화면이 사라짐 (2026-10-27)

**보고** (사용자, #209): 이미지 파일을 Finder에서 끌어다 놓으면 작업 환경이 다 사라지고 이미지만 열린다.

**원인**: 창의 네이티브 끌어 놓기 처리기를 꺼 두었다 (`dragDropEnabled: false`, 파일 트리 → 터미널·채팅 끌어 놓기를 위해).
그래서 끌기를 웹뷰가 처리하는데, 터미널·채팅 입력란은 파일 트리에서 끈 경로만 받고 앱 밖 파일은 아무도 받지 않는다.
받는 쪽이 없으면 WKWebView의 기본 동작이 놓은 파일로 이동하는 것이라 앱 화면이 그 그림으로 바뀌었다 (세션은 Rust에 살아
있지만 화면이 사라짐).

**수정** (두 겹):
- 화면: `dragPath.ts` `refuseOutsideDrops` (main.tsx에서 창 전체에). 아무도 받지 않은 `Files` 끌기는 dragover·drop의 기본
  동작을 막고 `dropEffect = "none"` (놓을 수 없게 표시). 파일 트리 경로·글자 끌기는 건드리지 않는다.
- Rust: `lib.rs` `stay_in_app` 플러그인의 `on_navigation`. 웹뷰가 앱 화면(`tauri://`, 개발 중에는 개발 서버와 같은 출처)과
  `about:` 밖으로 이동하지 않는다. 화면 쪽이 놓친 경우(웹 링크를 끌어 놓기 등)도 막는다. 링크는 원래 기본 앱으로 열어 웹뷰
  이동을 쓰지 않는다.

Finder에서 끈 파일을 받아 쓰기(터미널에 경로 넣기 등)는 이번 범위가 아니다 (spec: 앱 밖 파일은 받지 않음).

**확인**:
- Rust `webview_stays_on_app_pages`: tauri·about·개발 서버 출처는 허락, file·https·다른 포트·https 같은 호스트·data는 거절,
  설치한 앱(개발 서버 없음)에서는 localhost도 거절. Rust 118개 통과.
- 자체 테스트 `trashDrag`에 둘 추가:
  - "앱 밖에서 끌어 온 파일은 터미널·채팅 입력란·빈 곳 어디에도 받지 않음": `Files`가 든 합성 끌기의 dragover·drop이 막히고
    `dropEffect`가 none, 채팅 입력란 그대로.
  - "앱 화면 밖 주소로는 이동하지 않음": 숨긴 액자(iframe)로 시험 (창 전체로 하면 실패 때 테스트가 멈춘다). srcdoc(about:)은
    열려 postMessage가 오고, data: 주소는 열리지 않아 오지 않는다. wry의 이동 처리기는 액자에도 불린다.
- 수정을 끄고 확인: `refuseOutsideDrops`를 빼면 첫째 실패 (false×4), 플러그인을 빼면 둘째 실패 (data: 액자가 열림).
- 합성 이벤트는 실제 Finder 끌기가 아니다. 실제로 놓아 보는 확인은 맥 앞에서 (설치 후).
- 전체 `selftest.sh` (맥 화면 잠김): 새 검사 둘 통과, restart·corrupt·resume 통과. main 실패 5개:
  - 트리 화살표 회전·검색·WebGL: 변경 전 코드로도 잠긴 화면에서 실패하던 것 (`2026-10-27-chat-prompts.md`).
  - 배율 "실제 크기로 돌아오면": 그 단계만 다시 돌리면 통과 (시간 흔들림).
  - 작업그룹 끝내기 "세션을 모두 끝내고…": 백그라운드 작업 표시(late-marker)가 남음. 그 단계만 세 번 돌려 두 번 실패,
    수정을 끈 코드로도 실패해 이번 변경과 무관하다. 문서 탭 때 전체 실행에서는 통과했다. 끝내기가 SIGHUP을 무시하는
    백그라운드 작업을 가끔 못 끝내는지, 검사의 시간 문제인지는 따로 본다 (이번 범위 밖).
