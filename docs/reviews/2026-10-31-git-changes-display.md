# 저장소 행의 git 점, Git Graph의 커밋하지 않은 변경 (2026-10-31)

**요청** (사용자):
- 파일 트리에서 바뀐 것이 든 폴더에는 점이 보이는데 저장소 행에는 표시가 없다.
- Git Graph에 변경된 파일 수가 보이지 않는다. 보이는 방식은 물어서 "맨 위에 커밋하지 않은 변경 행, 누르면 바뀐 파일"로 정했다.

**원인**
- 저장소 행: `FileTree.tsx` `Children`이 저장소·worktree 항목에는 일부러 바깥 저장소 표시를 주지 않는다(`e.git ? undefined`).
  자기 저장소 표시는 펼친 뒤 그 안의 항목에만 붙고, 행 자체에는 붙일 곳이 없었다 (spec에도 "표시 없음"으로 적혀 있었다).
  프로젝트 폴더가 저장소가 아니고 그 안에 저장소가 있는 프로젝트(예: `ddak/ddak`)에서 바로 보인다.
- Git Graph: 커밋 그래프만 읽고 작업 트리 상태는 읽지 않았다 (기능 없음).

**수정**
- `src/gitStatus.ts`: `useGitStatus`의 구독 부분을 `useRepoFiles`로 나누고, `useGitSummary`·`gitSummary`(위치 아래 전체를
  폴더와 같은 규칙으로: 충돌 > 수정·삭제·이름 바뀜(M) > 추가·추적 안 함)를 더했다. 폴더 규칙은 `rank`·`inside`로 함께 쓴다.
- `src/FileTree.tsx` `Node`: 저장소·worktree 행은 `useGitSummary(그 폴더)`로 점을 보인다 (접혀 있어도). 같은 저장소를 펼치면
  그 안의 폴더들과 구독을 함께 써서 더 읽지 않는다. 보이는 저장소 행마다 3초마다 `git status`를 하나씩 더 돈다.
- `src/GitGraph.tsx`: 보이는 동안 지문 확인과 함께 `git_status`(open 없음)를 읽어, 바뀐 것이 있으면 목록 맨 위(가상 스크롤 밖)에
  "커밋하지 않은 변경 (N)" 행. HEAD 커밋 레인에 빈 원. 누르면 오른쪽에 바뀐 파일, 커밋을 고르면 커밋 상세로 (둘 중 하나만).
  저장소를 바꾸면 비우고, 읽기 실패나 변경 없음이면 행을 감춘다. 수는 작업그룹 끝내기 창과 같이 `status --porcelain` 줄 수다
  (추적 안 하는 폴더는 한 줄).
- `App.css`: 행 모양(흐름 배치, 흐린 기울임), 파일 상태 색 U(추가 색)·!(`s-X`, 오류 색). 문구 `git.uncommitted` (en·ko).
- spec "git graph", "사이드바 · 파일 트리"에 적음.

**확인**
- tsc 통과.
- 자체 테스트 `treeGit`: 접힌 저장소 행이 `M•`(수정 색), 펼친 뒤에도 저장소 행 `M•`, 커밋하면 사라짐. `gitSummary` 단위 검사
  (충돌·수정·추적 안 함·위치 아래만·빈 목록).
- 자체 테스트 `gitGraph`: 처음엔 행 없음 → 새 파일·수정 하나씩이면 맨 위 행 "Uncommitted Changes (2)", 누르면 M·U 파일,
  커밋을 누르면 그 상세로, 되돌리면 행이 사라짐.
- 대조: 저장소 행에서 `useGitSummary` 값을 버리면 `treeGit` 두 검사가, `git_status` 읽기를 빼면 `gitGraph` 검사가 실패한다.
- 전체 `scripts/selftest.sh`: 다섯 시나리오 모두 통과, PASS 534, FAIL 0.
