# 리뷰 대응: 다국어·테마 (2026-10-22)

## 1. 선택된 언어·테마를 다시 누르면 체크가 사라짐 (P2) — 타당, 재현됨, 수정

**지적**: View > Theme > Dark처럼 이미 선택된 항목을 다시 누르면 네이티브 체크가 꺼진다.
React 상태는 그대로라 메뉴 동기화가 다시 돌지 않는다.

**검증**
- muda 소스 `muda-0.20.0/src/platform_impl/macos/mod.rs:828-836`: 체크 항목의 클릭 동작(`Toggle`)은
  `state.checked = !state.checked`로 체크를 먼저 뒤집은 뒤 이벤트를 보낸다.
- `prefs.tsx`의 메뉴 동기화 효과는 `[locale, theme]`이 바뀔 때만 돈다. 같은 값을 다시 고르면 바뀌지 않는다.
- 기존 자체 테스트는 프론트에서 "menu" 이벤트를 직접 보내서 muda의 토글을 거치지 않았다.
  리뷰 지적대로 이 경로는 테스트가 잡지 못했다.
- **재현**: 네이티브 메뉴 항목을 실제로 실행하는 테스트 명령을 만들어(아래) 수정 전 코드로 돌렸다.
  Dark·English를 다시 누른 뒤 메뉴 상태 — 체크된 항목이 하나도 없음:
  `View/Theme/Dark, View/Theme/Solarized Light, View/Language/English, View/Language/한국어`

**수정** (`src/prefs.tsx`): 테마·언어 메뉴 이벤트가 올 때마다 카운터를 올리고, 메뉴 동기화 효과가
이 카운터에도 반응하게 했다. 값이 같아도 메뉴를 현재 상태로 다시 만든다.

**확인**: 수정 후 `View/Theme/Dark [x]`, `View/Language/English [x]` 유지. 한국어 메뉴에서
Solarized Light 재선택도 확인. 전체 자체 테스트 통과.

## 테스트 보강: 네이티브 메뉴를 실제 클릭 경로로 실행

- `selftest_click_menu` (`src-tauri/src/selftest.rs`): `NSApplication.mainMenu`에서 제목 경로로
  항목을 찾아 `performActionForItemAtIndex:`로 실행한다. 진짜 클릭과 같이 muda의 클릭 처리
  (체크 토글 포함)를 거친다. 자체 테스트의 언어·테마 전환은 모두 이 방식으로 바꿨다.
- 동기 Tauri 명령은 메인 스레드에서 돌 수 있어, 메인 스레드 작업을 기다리면 교착될 수 있다.
  그래서 async 명령으로 만들었다.
- 한계: 메뉴 항목 실행이지 키 입력(⌘W 등의 단축키 매칭)은 아니다.
