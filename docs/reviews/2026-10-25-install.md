# 리뷰 대응: 설치 스크립트 (2026-10-25)

리뷰 범위: `7539ebd` 이후 커밋 전 작업 트리 (`scripts/install.sh`, 식별자, 개발 데이터 폴더). 지적 네 건(P2 3, P3 1).
모두 소스로 확인했고 타당해서 고쳤다. 시험은 새로 만든 `scripts/test-install.sh`(임시 폴더의 가짜 앱)로 했고, 수정마다 예전
동작으로 되돌리면 실패하는 것을 확인했다.

앞서 확인한 것:
- 앱이 떠 있을 때 실제 설치: 종료 → 교체 → 다시 열기, 탭·세션 복원, 테마·배율 유지.
- ddak 터미널 종료를 흉내 낸 세션 분리 실험: setsid 자식은 살아남고, 같은 세션의 nohup 자식은 죽었다.

## 1. [P2] setsid 실패를 잡지 못함 — 타당, 수정

**검증**: Perl의 `POSIX::setsid()`는 실패하면 -1(참)을 돌려줘서 `or die`를 지나간다. setsid는 호출한 프로세스가 프로세스
그룹 리더이면 반드시 실패한다. 스크립트에서는 perl이 리더가 아니어서 앞의 실험이 통과했지만, 리더로 실행되면 조용히 분리되지
않는다.

**수정**: 먼저 fork해서, 그룹 리더일 수 없는 자식이 setsid한다. 반환값이 undef이거나 음수면 멈춘다.

**확인**: `test-install.sh` 6번. perl을 그룹 리더로 만든 뒤(`setpgrp` 뒤 exec) `--detach`가 떼어 내기를 돌면, 떼어 낸 명령의
세션이 시험 셸과 다르다. 예전 코드는 같은 세션인 채 오류 없이 지나가서 실패한다.

## 2. [P2] 동시에 설치하면 앱이 사라질 수 있음 — 타당, 수정

**수정**
- 교체 단계를 `lockf -k -t 300`으로 감싸 한 번에 하나만 돈다. 잠금(flock)은 명령이 끝나면(죽어도) OS가 풀어서 남는 잠금이
  없다. 처음에는 mkdir 잠금과 "쥔 프로세스가 죽었으면 넘겨받기"로 썼다. 그런데 넘겨받는 순간 다른 실행이 막 잡은 잠금을 지울
  수 있는 경쟁이 있어서 바꿨다.
- 준비 폴더는 실행마다 `mktemp -d`로 따로 만든다 (설치 경로와 같은 볼륨이라 mv가 바로 끝난다).

**확인**: `test-install.sh` 2번. 둘을 동시에 돌려도 앱이 남고(둘 중 하나), 남은 준비 폴더가 없다. 잠금과 실행별 폴더를 끄고 같은
준비 폴더를 쓰면 다섯 번 중 네 번 실패한다.

## 3. [P2] 마지막 이동이 실패하면 기존 앱을 잃음 — 타당, 수정

**수정**: 기존 앱을 지우지 않고 준비 폴더 안으로 옮겨 두고, 새 앱을 옮긴다. 옮기지 못하면 기존 앱을 되돌리고 실패로 끝낸다.
성공하면 준비 폴더째 지운다.

**확인**: `test-install.sh` 3번. 옮기기 실패를 주입하면(`DDAK_INSTALL_FAIL_MOVE=1`) 기존 앱이 그대로이고 준비 폴더가 남지
않는다. 되돌리기를 끄면 앱이 사라져 실패한다.

## 4. [P3] 예전 식별자의 실행 중인 앱을 끝내지 못함 — 타당, 수정

**수정**: 설치된 앱의 식별자를 먼저 읽고(바꿔도 되는 앱인지도 이때 확인) 그 식별자로 종료를 요청한다.

**확인**: `test-install.sh` 5번. 예전 식별자(`dev.ddak.desktop`)로 설치돼 실행 중인 가짜 앱에 그 식별자로 요청하고, 끝난 뒤
바꾼다. 새 식별자로 고정하면 실패한다.

## 시험 도구

- `install.sh`에 시험용으로 설치 경로·종료 명령·열기 명령·잠금 파일과 옮기기 실패 주입을 환경 변수로 둔다.
- `--detach`는 떼어 내기만 돌린다.
- 가짜 앱의 실행 파일은 `/bin/sleep` 링크다. 번들 안에 복사하면 서명 검사로 실행하자마자 죽는다 (Killed: 9).

## 후속 리뷰: 실패 처리 두 건 (P2) — 타당, 수정

### 되돌리기마저 실패하면 백업도 지워짐

**검증**: 소스. EXIT 정리가 준비 폴더를 무조건 지우는데 기존 앱 백업이 그 안에 있었다.

**수정**: 되돌리기에 실패하면 준비 폴더를 남기고(`keep`), "기존 앱은 <경로>에 있습니다"를 알린다.

**확인**: `test-install.sh` 7번. 새 앱 옮기기와 되돌리기를 모두 실패시키면(`DDAK_INSTALL_FAIL_MOVE=1`,
`DDAK_INSTALL_FAIL_RESTORE=1`) 알린 경로에 기존 앱이 그대로 있다. 남기기를 끄면 실패한다.

### 프로세스 조회 오류를 "실행 중이 아님"으로 봄

**검증**: 소스. `if pgrep …`은 오류(2·3)도 "없음"과 같이 다뤘다. 리뷰어 환경에서는 조회가 실제로 막혀서 그대로 바꾸고
성공으로 끝났다.

**수정**: `running()`이 `pgrep` 종료 코드를 직접 본다 (0 찾음, 1 없음, 그 밖은 오류로 교체를 멈춤). 처음 확인과 종료 대기가
모두 이 함수를 쓴다.

**확인**: `test-install.sh` 8번 (`DDAK_INSTALL_PGREP`로 조회 명령을 바꿈). 처음부터 오류(3)이면 바꾸지 않는다. 처음에는 찾고(0)
기다리는 동안 오류이면 바꾸지 않는다. 오류를 "없음"으로 되돌리면 둘 다 실패한다.

리뷰어 환경에서는 프로세스 조회 제한으로 5번(예전 식별자 종료) 시험이 실패했다. 이 기기에서는 통과한다.
