# 모바일 연결 3단계 리뷰 대응

대상: 브랜치 `ddak/mobile`, 기준 7bb9412(main) + 커밋 안 한 작업 트리. 범위(사용자 결정, 계획서 "3단계 세부"): 폰에서
프로젝트 열기, 안 읽은 수, 밝은 테마에서 폰 목록 글자가 흰색으로 보이는 문제. 잠자기 막기·알림 설정·컴퓨터 이름은 하지 않는다.

## 구현 요약

- `chat.rs`: `Chats::unread`(본 번호 뒤, 본 적 없으면 앱을 켠 뒤 온 것)·`seen`(앞으로만, 처음엔 켜기 전 마지막 번호보다 앞으로
  가지 않음, 올라가면 `Change::Seen` → 프론트 `chat-seen`, 폰 SSE `unread`). 명령 `chat_unread`·`chat_seen`, 자체 테스트용
  `selftest_chat_post`.
- `ChatPanel.tsx`: 안 읽은 수를 직접 세지 않고 Rust에서 읽는다. 보고 있으면 `chat_seen`.
- `mobile.rs`: `set_opened`(프론트가 연 프로젝트), `/api/projects`의 `open`·`unread`, members의 `open`, `POST …/open`(열리지 않은
  것만 프론트에 `mobile-open`), `POST …/read`.
- `App.tsx`: `set_opened` 알림, `mobile-open`이면 활성 프로젝트를 그대로 두고 연다. `useProjects.add(path, activate)`
  (자체 테스트가 목록에만 넣으려고).
- 폰: 목록에 "맥에서 열리지 않음"·안 읽은 수 배지, 채팅에 "맥에서 열기", 보이는 채팅에서 받은 마지막 번호를 `read`로.
  `mobile.css`의 배경 없는 버튼 글자색 `--fg`.

## 확인

- Rust 121개 통과. 새 시험: `unread_after_seen_and_start`, `open_and_read_from_phone`.
- 전체 자체 테스트 5개 시나리오 통과 (PASS 461). 새 검사: mobile 단계의 안 읽은 수(맥 배지 = 폰 목록, 폰에서 읽으면 맥 배지 지움)와
  폰에서 열기(목록에만 있는 프로젝트를 열고 활성 프로젝트는 그대로), `mobileThemeUnit`(두 테마에서 프로젝트 이름·‹·+ 글자색).
- 변이 확인 7건 (CSS 글자색, `mobile-open` 수신, `chat-seen` 등록, read 무시, 켜기 전 기준, 처음 본 번호 기준, 열린 것 다시 열기):
  모두 해당 시험이 실패했다. 확인 뒤 소스를 되돌리고 다시 빌드했다.

## 1차 리뷰 (채팅 #228)

| ID | 심각도 | 판단 | 근거 | 수정 | 확인 |
|---|---|---|---|---|---|
| R1 | P2 | 타당 | `markRead`가 SSE 메시지마다 돌아, 최신 조회가 아직 성공하지 않았거나 실패한 상태에서도 SSE 한 건의 번호로 읽음을 보냈다. `Chats::seen`은 그 이하를 모두 읽음으로 친다. | `MessageView`에 맞춘 상태(`synced`): 최신 조회 적용 때 켜고 조회 시작 때 끈다. `readable()`은 맞춘 상태에서만 마지막 번호. | `mobileSyncUnit`: 조회 중 SSE 101 → 0, 실패 → 0, 성공 → 101, 그 뒤 SSE 102 → 102. `synced`를 무시하면 실패. |
| R2 | P2 | 타당 | 화면이 보이는지만 보고 맨 아래를 보는지는 보지 않아, 위쪽 기록을 읽는 동안 온 새 메시지까지 읽음이 됐다. | `readTarget(view, visible, atBottom)`: 맨 아래를 볼 때만. 아래로 내려오면(`onScroll`) 다시 알린다. | `mobileSyncUnit`: 위쪽·숨김이면 0. `atBottom`을 무시하면 실패. |
| R3 | P2 | 타당 | `/read` 실패를 숨기고 다시 보내지 않았다. | `ReadMark`: 보낸 번호 이하는 다시 보내지 않고, 실패하면 5초 뒤 같은 번호로 다시. 그 사이 더 뒤 번호를 보내면 그것만. 화면을 떠나면 멈춘다 (StrictMode에서도 되게 효과 안에서 만든다). | `mobilePushUnit`: 실패한 100을 저절로 다시 보냄, 99·100은 다시 안 보냄, 101 실패 중 102를 보내면 102만. 다시 보내기를 빼면 실패 (처음 쓴 검사는 이 변이를 잡지 못해 다시 보내기 직후를 보게 고쳤다). |
