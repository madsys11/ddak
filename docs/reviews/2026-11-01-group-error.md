# 작업그룹 만들기 오류: 개발자 모드 안내, 성공하면 지우기 (2026-11-01)

## 문제

- Windows에서 개발자 모드가 꺼진 채 작업그룹을 만들면 프로젝트 루트의 저장소 아닌 항목(`.claude`)을 링크하지 못해
  `Could not create the work group: .claude: 클라이언트가 필요한 권한을 가지고 있지 않습니다. (os error 1314)`가 떴다.
  `docs/windows-plan.md`는 "못 만들면 이유와 함께 알린다"였지만 OS 오류가 그대로 보였다. 되돌리기는 맞게 됐다
  (각 저장소에 `main` worktree·브랜치만 남음).
- 개발자 모드를 켜고 다시 만들어 성공해도 사이드바(파일 트리 위)의 오류가 남았다. 오류 칸(`useProjects`의 `error`)은
  프로젝트 추가가 성공할 때만 지워졌다.

## 수정

- `platform::link_privilege_missing`: Windows의 `ERROR_PRIVILEGE_NOT_HELD`(1314)인지. 작업그룹의 링크(`worktrees.rs`)와
  로컬 저장소 연결(`repos.rs`)이 이때 `linkPrivilege` 코드(자세한 값은 항목 이름)를 돌려준다. 프론트는 개발자 모드를 켜라는
  문구로 보인다 (`group.linkPrivilege`, `repo.error.linkPrivilege`). 남은 작업그룹 다시 쓰기(reuse)의 링크 실패는 전처럼
  그 폴더를 건너뛰고 새로 만들기로 가서 같은 안내가 뜬다.
- `Workspace.createGroup`: 오류를 띄울 때 App이 돌려준 값(띄운 호출의 표시)을 기억하고, 다음 만들기가 성공하면
  `onClearError(그 값)`. App은 마지막으로 Workspace가 띄운 오류가 그 호출의 것이고 지금 보이는 문구도 같을 때만 지운다
  (다른 프로젝트가 같은 문구로 띄운 오류, 그 사이 다른 곳이 띄운 오류는 남긴다).
- 오류에 닫기 단추를 두는 방법은 넣지 않았다 (요청 범위가 아님).

## 확인

- `cargo test` 92개 통과 (새 `link_privilege_missing_only_for_1314_on_windows`). 개발자 모드를 켠 뒤라 전에 실패하던
  링크 테스트 11개도 통과.
- 자체 테스트 새 단계 `groupErrorClear` (Windows에서 main 시나리오로 돌림, 통과): 저장소 없는 A·B가 같은 문구로 실패 → A를
  고쳐 성공해도 B의 오류는 남음 → B를 고쳐 성공하면 사라짐 / B가 다시 실패 → 다른 오류(없는 폴더 추가) → 성공해도 다른 오류는
  남음. 따로 만든 프로젝트에서 해서 root의 작업그룹 번호에 끼어들지 않는다.
- 수정을 끄고 확인: 성공 때 지우기를 빼면 "사라짐"이 실패, 문구만 비교하게 하면 "다른 프로젝트가 같은 문구로 띄운 오류는
  지우지 않음"이 실패 (R1 전 코드), 무조건 지우게 하면 "다른 곳이 띄운 오류는 지우지 않음"이 실패 (첫 구현 때 확인).
- 못 한 것: 개발자 모드 안내 문구를 실제 1314로 띄워 보지는 못했다 (이 PC는 개발자 모드를 켰다). 판정 함수는 단위 테스트로,
  코드→문구 연결은 읽어서 확인. 맥 selftest는 돌리지 못했다.
