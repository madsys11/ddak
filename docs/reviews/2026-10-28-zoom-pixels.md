# 화면 배율의 터미널 번짐 (2026-10-28)

## 측정

레티나(실제 비율 2)에서 배율 단계마다 터미널 WebGL 캔버스의 픽셀 수, 화면에 보이는 크기(CSS 크기 × 배율 × 2), 위치를
쟀다(임시 자체 테스트 단계, 지금은 testZoom에 들어감). 고치기 전:

| 배율 | 캔버스 | 보이는 크기 | 위치 |
|---|---|---|---|
| 0.5 | 2268×1470 | 2268×1470 | 272, 66 |
| 0.67 | 2170×1449 | 2169.44×1448.53 | 363.09, 87.03 |
| 0.8 | 2100×1416 | 2100.78×1416 | 432.78, 103.19 |
| 0.9 | 2044×1404 | 2044.78×1404 | 486.38, 115.59 |
| 1 | 1980×1410 | 1980×1410 | 540, 128 |
| 1.1 | 1921×1386 | 1920.59×1386 | 593.59, 140.37 |
| 1.25 | 1843×1368 | 1842.5×1367.5 | 674, 159 |
| 1.5 | 1702×1305 | 1701×1305 | 810, 192 |
| 1.75 | 1539×1272 | 1540×1270.5 | 944, 223 |
| 2 | 1395×1260 | 1396×1260 | 1080, 256 |

원인: xterm WebGL 렌더러(`WebglRenderer.ts` _updateDimensions)가 캔버스 CSS 크기를 Math.round(캔버스 픽셀 ÷ dpr)로 둔다.
Chromium은 devicePixelContentBoxSize로 캔버스 픽셀 수를 고치지만 WebKit에는 그 API가 없다. 배율 1에서도 칸 수가 홀수면
(셀 폭 15 기기 픽셀) 0.5 CSS px가 반올림돼 어긋난다.

## 수정

`src/zoom.ts` alignToPixels: devicePixelContentBoxSize가 없을 때만 캔버스 style 크기를 소수 그대로 두고, `.xterm-screen`을
translate로 옮겨 화면 픽셀 경계에 맞춘다. 고친 뒤 열 단계 모두 보이는 크기 = 캔버스, 위치 정수.

확인: testZoom sharp()를 엄격하게(오차 0.02) 바꾸고 0.5~2배 모든 단계를 돈다. 고친 것을 끄면 8개 배율에서 실패.
이 검사는 픽셀 정렬의 근거이고, 글자 모양을 눈으로 비교한 결과는 아니다 (이 환경은 화면 캡처가 안 된다).

## 글자 폭 (참고)

번짐과 별개로, xterm은 칸 폭을 floor(글자 폭 × dpr)로 둬서 Menlo(글자 폭 0.602em)는 칸보다 조금 넓다. 레티나에서 기본
13px은 4.2%, 12.5·15·17.5·20·22.5·25px은 0.3%. 계산값이며 눈으로 비교하지 않았다.
