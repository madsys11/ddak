# 계획 문서도 리뷰받기 (협업 규약 7번)

대상: 기준 efc7a76(main) + 커밋 안 한 작업 트리 (`src-tauri/src/groups.rs`, `docs/spec.md`).

## 배경

사용자가 써 보니 개발 세션이 계획 문서를 쓴 뒤 리뷰어에게 리뷰를 요청하지 않고 사용자에게 바로 갔다. 규약에는 리뷰 횟수(4번)와
요청에 적을 대상(5번)만 있고, 무엇을 리뷰받는지·누가 언제 요청하는지는 없어서 세션이 "변경"을 코드로만 읽은 것으로 본다.

## 바꾼 것 (사용자 승인 2026-10-28)

- 규약 7번: 사용자 승인으로 가기 전에 리뷰를 받는다. 코드 변경뿐 아니라 계획·설계 문서(새 계획, 결정이나 스펙 변경)도.
  초안이 되면 시키지 않아도 스스로 리뷰어에게 요청한다.
- 리뷰어 역할: 계획·설계 문서는 코드와 사용자 요청에 비추어 빠진 경우, 틀린 가정, 위험, 더 단순한 대안을 본다.
- 기본 설정(`groups.rs` RULES·REVIEWER_ROLE)과 스펙의 협업 규약. 이미 있는 `groups.json`은 바뀌지 않으므로, 사용자의 설치된
  앱 설정에는 같은 문구를 두 줄만 바꿔 넣었다 (사용자 승인. 이미 연 세션은 띄울 때의 프롬프트를 계속 쓰고 새 세션부터 적용).
