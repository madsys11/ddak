# 폰 화면 설정: 글자 크기, 테마, 언어 (2026-10-28)

사용자 요청: "모바일 앱에도 폰트크기변경과 테마, 언어 반영해줘".

## 해석

데스크톱은 보기 메뉴에서 배율, 테마, 언어를 고른다. 폰 화면에는 메뉴가 없어서 언어는 폰 설정을, 테마는 폰 밝기를 따르기만 했다.
폰 화면에 설정 화면을 두고 셋을 고르게 했다. 기본값은 예전 동작 그대로(폰 설정 따라, 100%)라서 고르지 않으면 바뀌는 것이 없다.

맥의 설정을 폰으로 옮기는 방식은 택하지 않았다. 폰은 여러 맥에 이어질 수 있고, 화면 크기와 쓰는 상황도 맥과 다르다.

## 구현

- `src/mobile/settings.ts`: 설정을 읽고, 검사하고, 저장한다 (`ddak.phone.settings`). 폰 설정 따라의 해석과 적용도 여기서 한다.
- 설정 화면 (`MobileApp.tsx` `Settings`, `#/settings`): 막대의 ⚙로 연다. 컴퓨터 추가, 컴퓨터 목록, 프로젝트 목록에 있다.
- 테마
  - 폰 설정 따라는 예전과 같다 (어두우면 Dark, 밝으면 Solarized Light).
  - 고르는 목록은 데스크톱의 `THEMES` 그대로라, 새 Light도 들어 있다.
- 언어: 문구 함수 `t`가 시작할 때 언어를 고정한다. 그래서 지금과 다른 언어를 고르면 화면을 다시 읽는다.
  모든 화면을 언어 상태에 묶는 것보다 단순하다.
- 글자 크기
  - `mobile.css`의 글자 크기 15곳을 `calc(Npx * var(--font-scale, 1))`로 바꿨다. 글자만 커지고 여백·버튼 크기는 그대로다.
  - 입력란은 `max(16px, …)`다. iOS Safari는 16px보다 작은 입력란에 포커스하면 화면을 확대하므로 85%에서도 16px을 지킨다.
- 고른 버튼은 선택 행 색(`--row-active`)과 포커스 테두리 색으로 보인다.
  색을 채운 강조색은 Solarized에서 흰 글자 대비가 낮아 쓰지 않았다.

## 확인

자체 테스트 `mobileSettingsUnit`은 실제 설정 화면을 iframe에 그리고 적용·다시 읽기만 대역으로 바꾼다.

- 깨진 저장값과 모르는 값은 기본값이 되고, 맞는 값은 그대로다.
- 폰 설정 따라의 해석: 밝기에 따른 테마, 폰 언어.
- 테마 목록은 폰 설정 따라와 모든 테마다. 처음에는 폰 설정 따라가 골라져 있다.
- 테마·글자 크기를 누르면 바로 적용하고, 저장하고, 고른 것을 표시한다.
- 지금과 다른 언어를 고르면 다시 읽고, 같은 언어면 그대로 적용한다.
- 배율 1.3에서 본문 20.8px, 작은 글자 18.2px, 제목 22.1px이다.
  배율 0.85에서 본문 13.6px, 입력란은 16px이다.

수정을 끄고 돌린 결과:
- 입력란 하한, 언어 다시 읽기, 저장값 검사를 함께 끄면 해당 검사 3개가 실패한다.
- 배율 변수를 빼면 글자 크기 검사가 실패한다.

`npm run build:mobile`도 성공한다.

실기기(iPhone)로는 확인하지 못했다. 폰 화면은 main에 push하면 GitHub Pages(`mobile-pages.yml`)로 배포된다.

전체 자체 테스트:
- 새 단계(`mobileSettingsUnit`)와 다른 시나리오는 통과했다.
- main 시나리오는 화면 잠금(`CGSSessionScreenIsLocked`) 상태라 앞서와 같은 트리 화살표, 폰 채팅, 배율, WebGL이 실패했다.
- 그 밖에 채팅 깨우기와 `lastExit`(빈 화면 기다림 시간 초과)도 실패했다. `lastExit`은 혼자 두 번 돌려 두 번 다 통과했다.
- 화면 잠금이 풀린 뒤 다시 돌려야 전체 통과로 볼 수 있다.

## 리뷰 1차 (리뷰어 #321): P2 두 건

### R1 상속 키가 저장값 검사를 통과함 — 타당, 수정 (데스크톱 포함)

확인: `isThemeId`·`isLocale`은 `v in THEMES`로 검사해서 `"constructor"`, `"__proto__"`, `"toString"`도 통과한다
(`node`: `"constructor" in {dark:1}`는 true). 폰은 이 값을 받아 `applyTheme`·`translate`에서 예외가 나고 시작이 멈춘다.
데스크톱 `prefs.tsx`도 같은 함수로 localStorage의 테마·언어를 검사하므로 같은 문제가 있다.

수정: 두 함수를 `Object.hasOwn`(자기 키만)으로 바꿨다. 폰과 데스크톱이 함께 고쳐진다.

확인: 상속 키 네 개로 된 저장값은 기본값이 되고, `isThemeId`·`isLocale`도 거절한다. `in`으로 되돌리면 실패한다.

### R2 저장하지 못했는데 언어를 바꾸며 다시 읽음 — 타당, 수정

확인: `saveSettings`가 예외를 삼키고, 설정 화면은 저장 여부와 관계없이 다시 읽었다.
다시 읽으면 저장된 이전 언어로 돌아가서 언어가 바뀌지 않는다.

수정:
- `saveSettings`가 저장했는지 돌려준다.
- 저장하지 못하면 알림(`phone.settingsUnsaved`)을 보인다.
  언어는 바꾸지 않고(고른 표시도 그대로, 다시 읽지 않음), 테마·글자 크기는 지금 화면에만 적용한다.
- 다시 저장되면 알림이 사라진다.

확인: `Storage.prototype.setItem`이 예외를 던지게 하고 다른 언어를 누르면 다시 읽지 않고 알린다. 테마는 적용하고 알린다.
저장 여부를 보지 않게 되돌리면 실패한다.
