# 받는 사람 없는 사용자 메시지는 보내지 않기 (2026-10-27)

**요청** (사용자, 폰에서): 채팅에서 실수로 전체 메시지를 보냈다. 기본이 전체 전송보다는 `@all`을 명시적으로 고르게 하는 게
맞겠다. 제안(#186)대로 진행. 리뷰 세션 보완(#187): "@가 있는가"가 아니라 보내는 순간 실제로 받을 세션이 있는가로 보고,
끝난 세션만 고른 경우·칩을 고른 직후 세션이 끝난 경우도 맥·폰 서버가 같은 규칙으로 막는다 — 타당, 그대로 반영.

**구현** (spec "채팅방 설계" 메시지, 자동 깨우기 제한 풀기, 채팅 패널, 모바일 API):
- `chat.rs` `post_via`: 받는 사람은 멘션된 지금 참여자(`@all`이면 모두). 사용자 메시지에 받을 참여자가 없으면 저장하지 않고
  `NO_RECIPIENT`("no-recipient") 오류. 같은 잠금 안에서 정하므로 칩을 고른 뒤 세션이 끝나도 보내는 순간의 참여자로 본다.
  세션의 메시지는 그대로 (멘션이 없으면 기록만).
- 맥 채팅 패널(`chat_post`)·폰(`POST …/messages` → 400 `{"error":"no-recipient"}`)이 같은 함수를 지나므로 예전 폰 화면도 막힌다.
- 화면: 맥 채팅 패널과 폰에 "모두 (@all)" 칩 (세션이 있을 때 맨 앞), `no-recipient`면 초안을 남기고 받는 사람을 고르라는 안내
  (`chat.noRecipient`), 입력란 안내 문구에서 "모두에게"를 뺌. 보내면 안내를 지운다.
- 자체 테스트용 `selftest_chat_join`·`selftest_chat_leave` (`DDAK_SELFTEST`일 때만): 터미널 없이 참여자를 넣는다. 폰 보내기
  검사(mobile 단계)와 두 번째 프로젝트의 채팅 검사(projects 단계)에 받는 사람이 필요하다.

**확인**:
- Rust 116개 통과. 바꾼 테스트: `names_mentions_and_file`(멘션 없으면 `no-recipient`·저장 없음, `@all`은 모두),
  `mention_of_left_session_is_not_broadcast`(나간 세션·모르는 이름만이면 거절, 저장 없음), `projects_messages_and_post`(폰: 받을
  세션이 없으면 400 `no-recipient`, 참여자를 멘션하면 200·`via`). 사용자 메시지로 저장만 보던 테스트(지우기, 깨진 줄, 읽을 수
  없는 파일, 폰 목록 페이지)는 세션 메시지로 바꿈.
- 자체 테스트(mobile, projects, addSession) 통과: 폰에서 멘션 없이 보내면 400·저장 없음, `@all`이면 사용자로·기기 이름,
  채팅 패널에서 멘션 없이 Enter → 안내·초안 남음·저장 없음, `@all` 칩 → `@all ` 넣기·모두에게·안내 사라짐.
- 수정을 끄고 확인: 예전 규칙(멘션 없으면 모두)으로 되돌리면 Rust 2개와 채팅 패널 검사 실패, 받는 사람 없음 거절을 끄면
  Rust 3개(폰 포함) 실패.
- 전체 `selftest.sh` (맥 화면 잠김): PASS 433, restart·corrupt·resume 통과. main 실패 4개(트리 화살표 회전, 탭 폭 복원, WebGL,
  lastExit 빈 화면)는 선택 창 답하기 때 잠긴 화면에서 본 것과 같은 것으로, 이번 변경과 닿지 않는다 (`2026-10-27-chat-prompts.md`).
