질문 답:
- SSE: `fetch` 스트림으로 받는다 (`EventSource`는 `Authorization` 헤더를 넣을 수 없음). 토큰을 URL에 싣지 않는다. 문서 "모바일 서버"에 추가.
- 푸시 권한 회수: 폰 목록에서 빼는 것만으로는 회수가 아니다. 폰이 지금 구독 해지 → 새 키 → 새 구독 → 남은 컴퓨터에 전달하는 "알림 키 바꾸기"가 회수다. 꺼져 있던 남은 컴퓨터는 다음 연결 때 받는다. 문서 "여러 컴퓨터: 푸시 알림"에 추가.
- 읽음 이전: 필터는 지금과 같이 `from != user && to.includes(user)`. 데스크톱은 `set_view`로 추측하지 않고, 지금 `ChatPanel`이 "보고 있음"일 때 `seen`을 올리는 자리에서 `chat_seen`으로 Rust에 알린다 (새 메시지 도착·창이 다시 앞으로 올 때의 지금 동작 그대로). 문서 "안 읽은 수"에 추가.

Android 우선 반영: M0를 Android Chrome 기준으로 다시 씀. 실제 공개 HTTPS 출처에서 두 `*.ts.net`으로, Chrome LNA 권한(처음 허용·거절·철회 후 복구), PWA 다시 실행, VPN 다시 이어짐, A가 꺼진 상태에서 B 사용, 푸시 권한 거절·철회, 키 바꾸기 뒤 예전 키 거절. iOS는 지원 대상으로 두고 실기기 확인을 미룸 (D1).
