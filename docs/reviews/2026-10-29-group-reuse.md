# 작업그룹: 남은 것 다시 쓰기와 마지막 탭을 닫을 때 끝낼지 묻기 (2026-10-29)

**보고** (사용자 #359): 새 작업그룹을 열면 번호가 늘어나는데, 모든 작업그룹을 닫아도 계속 는다. 모두 닫으면 기본(처음 번호)이
열려야 할 것 같다.
**원인**: 탭을 ×로 닫으면 탭만 닫히고 worktree 폴더와 브랜치(`ddak/<이름>`)는 남는다 (일부러 지우지 않는 설계). 새 작업그룹은
"폴더도 브랜치도 없는 첫 번호"를 쓰므로 남은 것만큼 번호가 오른다. 실제로 ddak 프로젝트에 탭 없는 dev-review-1~8이 남아 있었다
(모두 고친 것 없음, 브랜치는 origin/main에 다 있음).
**결정** (사용자 #360 제안 → #361 "1", #362 "2번도 하자"): ① 남은 작업그룹을 다시 쓴다, ② 마지막 탭을 닫을 때 끝낼지 묻는다.
지금 남은 dev-review-1~8은 정리하지 않는다 (①로 다시 쓰인다).

## ① 남은 작업그룹 다시 쓰기 (`worktrees.rs` reuse)

새 작업그룹을 만들 때 같은 그룹의 `<그룹>-<번호>` 폴더를 번호 작은 것부터 보고, 다음을 모두 만족하는 첫 것을 쓴다. 없으면 예전처럼
새 번호. 조건은 "다시 써도 잃는 것이 없다"를 끝내기와 같은 기준으로 본다:
- 지금 쓰지 않음: 프론트가 이 프로젝트 탭들의 폴더를 `inUse`로 넘기고 (`Workspace.tsx` createGroup), Rust는 그 폴더 안의 ddak
  터미널(닫는 중 포함, `pty::running_under`를 pub로)도 본다. 실제 경로로 비교.
- 만든 기록이 있고, 기록의 (저장소, worktree, 브랜치)가 지금 프로젝트로 새로 만들 것(`plan`)과 같음.
- `status_of`(끝내기와 같은 검사)에서 `blocked()` 없음 + 빠진 worktree 없음 + 원본 HEAD에 병합 안 된 커밋 없음.
- 각 worktree가 기록한 브랜치에 있고 HEAD가 원본 HEAD의 조상. 확인을 모두 마친 뒤에만 `merge --ff-only`로 앞으로 감는다 (앞으로
  감기만 하므로 중간에 실패해도 잃는 것은 없다). 원본의 저장소 아닌 항목 중 없는 링크를 더하고, 기록의 시작 커밋을 고친다.
- 준비(setup: 복제·준비 스크립트)는 새로 만들 때처럼 돈다 (`group_create`가 그대로 계획한다).

## ② 마지막 탭을 닫을 때 끝낼지 묻기 (`Workspace.tsx`, `EndGroupDialog.tsx`)

탭의 ×, 창의 ×, ⌘W(메뉴 `close_pane`)는 닫기 동작에 `ask`를 붙인다. 리듀서가 그때의 상태로 그 닫기가 작업그룹(새 worktree)의
마지막 탭을 닫게 되는지 보고 (`lastOfGroup`: 같은 폴더를 쓰는 다른 탭 없음), 그러면 닫지 않고 `askClose`(저장하지 않음)를 남긴다.
Workspace가 그것을 보고 작업그룹 끝내기 창을 연다. 처음에는 컴포넌트에서 판단했는데, ⌘W 메뉴 이벤트가 빠르게 이어지면 컴포넌트의
상태가 한 번 늦어 두 번째 ⌘W가 이미 닫은 창을 가리켜 아무것도 닫지 못했다 (자체 테스트 tabScroll 등에서 드러남). 리듀서로 옮겨
늘 그때의 상태로 판단한다. 창에
안내("이 작업그룹의 마지막 탭입니다…")와 "탭만 닫기" 단추를 더한다 (`onCloseTab`). 끝내기는 원래 창 그대로 (상태를 보이고 끝낼
수 있을 때만). 같은 폴더를 쓰는 다른 탭이 있거나 원본 탭이면 묻지 않는다. 프로그램이 스스로 끝나 닫히는 것(`exit` → onExit)은
묻지 않는다.

## 리뷰 1차 (reviewer-2 #371)

**R1 [P0] 앞으로 감기가 무시된 로컬 파일을 덮어씀 — 타당.** `status --porcelain`은 무시된 파일을 세지 않고, `merge --ff-only`는
원본이 같은 경로에 추적 파일을 더하면 무시된 파일을 덮는다 ("앞으로 감기만 하므로 잃는 것이 없다"가 틀렸다).
수정: 감기 전에 `git diff --name-only --no-renames --diff-filter=A -z <지금 HEAD> <대상>`으로 새로 생길 경로를 얻고, 그 자리나 그
상위 경로(폴더가 아닌 것)에 이미 무엇이 있으면 그 후보를 건너뛴다 (커밋 안 한 변경이 없으니 있다면 무시된 파일·폴더다).
확인: Rust `reuse_skips_what_it_could_lose` — g-1에 무시된 local.txt(PRIVATE), 원본이 ignore를 지우고 local.txt를 커밋 → g-1을
건너뛰고 PRIVATE 그대로. 검사를 빼면 g-1을 써서 실패.

**R2 [P2] 같은 브랜치를 다른 worktree가 체크아웃했는지 안 봄 — 타당.** 그쪽 HEAD가 함께 움직여 인덱스·파일과 어긋난다.
수정: `branch_in_use`를 `branch_in_use_except(repo, branch, own)`로 넓혀, 후보 자신의 git 폴더(`rev-parse --absolute-git-dir`)는
HEAD만 빼고 (진행 중인 rebase·bisect는 본다) 다른 checkout이 쓰면 건너뛴다. 확인하지 못하면 건너뛴다.
확인: 같은 테스트에서 ddak/g-2를 다른 worktree에 `--force`로 체크아웃 → g-2를 건너뛰고 그쪽 HEAD 그대로. 검사를 빼면 g-2를 써서 실패.

**R3 [P2] 다시 쓴 뒤 예전 준비 성공 기록을 믿고 설치를 건너뜀 — 타당.** 진행 기록(`.ddak-state-<이름>.json`)의 install·clone
성공이 남아, 바뀐 lockfile에도 `npm ci`를 건너뛰었다.
수정: 다시 쓰기 전에 `prepare::forget_installs`로 설치·복제의 시작·성공 기록을 지운다. 가상 환경·만든 폴더(made) 기록은 둔다
(그 폴더가 우리 것인지 알아야 다시 만들 때 지울 수 있다). 기록 파일이 없으면 할 것 없음, 지우지 못하면 그 후보를 쓰지 않는다.
확인: 같은 테스트에서 g-3 기록의 install·clone이 지워지고 venv와 made는 남음. 지우기를 빼면 실패.

## 재리뷰 1회 (reviewer-2 #377)

R2·R3 해결 확인. **R1 남음 [P0] — 타당.** 공용 `git()`이 표준 출력 전체를 `trim()`해서, `-z` 경로 목록의 첫 경로가
" secret.local"처럼 공백으로 시작하면 "secret.local"로 바뀌어 검사를 지나쳤다. 그 뒤 앞으로 감기가 무시된 " secret.local"을 덮었다.
수정 (두 겹):
- 경로 목록은 `git_bytes`(자르지도 UTF-8로 바꾸지도 않는 출력)로 받아 NUL로 나누고 유닉스에서는 바이트 그대로 경로로 만든다
  (`nul_paths`). UTF-8이 아닌 이름도 바뀌지 않는다 (APFS는 UTF-8이 아닌 이름을 만들 수 없어 시험하지 않았다).
- 앞으로 감기를 `merge --ff-only --no-overwrite-ignore`로: 무시된 파일을 덮게 되면 git이 멈춘다 (git 2.39 `merge -h`:
  `--overwrite-ignore`가 기본). 위 검사가 놓치는 경우의 두 번째 막이.
확인: `reuse_skips_what_it_could_lose`의 g-1을 이름 앞에 공백이 있는 무시된 " secret.local"로 바꿨다 (원본이 같은 이름을 커밋).
g-1을 건너뛰고 PRIVATE 그대로. 대조: 예전 경로 처리(trim) + git 막이 없음 → g-1을 써서 실패 (리뷰 재현). 예전 경로 처리만 → git
막이가 막아 통과. git 막이만 뺌 → 새 경로 처리로 통과. 두 겹이 각각 막는다. Rust 132개 통과.
- 전체 `selftest.sh` (화면 꺼짐, 08:18부터): restart·corrupt·resume 통과. main은 트리 화살표, 폰 채팅 1건, 배율 캔버스 4건,
  terminalContrast(main의 새 단계, 300초 시간 초과)가 실패. 이번 수정은 Rust worktrees.rs뿐이고 화면이 켜져 있던 바로 앞 전체
  실행(R1 수정 전 같은 프론트 코드)은 다섯 시나리오 모두 통과(PASS 507)라 화면 꺼짐 때문으로 본다. 이번 변경이 닿는
  작업그룹 단계(repos~gitGraph)는 다시 돌려 통과. 화면이 켜지면 전체를 다시 돌려 확인한다.
