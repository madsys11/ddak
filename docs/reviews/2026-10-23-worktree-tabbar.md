리뷰 범위: `35bc11e` 이후 커밋 전 작업 트리. P2 6건 모두 타당, 수정.
지적마다 수정 전 코드에서 실패하는 테스트를 먼저 넣고 실패를 확인한 뒤 고쳤다.

## 1. 실패한 `worktree add`가 남긴 브랜치·등록 정보를 지우지 않음 (`worktrees.rs`) — 타당, 수정

**검증**: 실험. post-checkout 훅이 `exit 1`인 저장소에서 `git worktree add -b ddak/x <폴더> HEAD`
→ 종료 코드 1인데 브랜치 `ddak/x`와 worktree 등록이 남는다 (git 2.39.5). `Undo`에는 성공한 명령만 들어가서
이것이 남았고, 같은 이름으로 다시 만들 수도 없었다.

**수정**: worktree 등록은 명령 전에 정리 목록에 넣는다 (폴더가 방금 만든 그룹 폴더 안이라 우리 것이다).
브랜치 소유권은 처음에 "직전 확인 후 정리 목록에 넣기"로 했다가 후속 리뷰 P1로 바꿨다 (아래 후속 리뷰 참고).

**확인**: Rust 테스트 `failed_add_cleans_up_its_own_branch` — 두 번째 항목(web)에서만 실패하는 훅으로 만들기 실패
→ `ddak/*` 브랜치 없음, worktree 목록에 없음, 훅을 지우면 같은 이름(dev-1)으로 다시 만들어짐. 수정 전 코드에서 실패.

## 2. 작업그룹으로 바꾼 뒤에도 원본 파일을 고칠 수 있음 (`Sidebar.tsx`) — 타당, 수정

**검증**: 소스 확인. `Children`이 같은 컴포넌트로 남아 `path`만 바뀌므로, 새 `list_dir` 응답이 올 때까지 이전 폴더의
항목이 그대로 그려진다. 자체 테스트로 재현: React가 그릴 때마다 (MutationObserver) 트리를 봤더니 작업그룹 표시
`test-1`과 원본 `proj/A_dir` 행이 같이 있었다 (원본으로 돌아갈 때도 반대로 같은 현상).

**수정**
- `<Children key={shown}>`: 루트가 바뀌면 새로 그려 이전 항목을 바로 버린다.
- 트리 루트가 바뀌면 새 항목 입력란·이름 바꾸기·오른쪽 클릭 메뉴를 닫는다. 입력란은 탭을 바꿀 때 터미널이
  포커스를 가져가 blur로 이미 닫혔지만 (그래서 입력란 테스트는 수정을 꺼도 통과해서 버렸다), 메뉴는 이전 폴더
  경로로 만든 항목을 가진 채 열려 있었다.

**확인**: 자체 테스트 "트리 루트가 바뀔 때 이전 폴더 항목이 남지 않음", "트리 루트가 바뀌면 오른쪽 클릭 메뉴를 닫음".
둘 다 수정 전 코드에서 실패. 리뷰처럼 응답을 늦추지는 않았다 (항목이 남는지는 그린 직후를 보는 것으로 충분하다).

## 3. 이름을 정할 때 항목 이름이 붙은 브랜치를 검사하지 않음 (`worktrees.rs`) — 타당, 수정

**검증**: 소스 확인. 후보 번호마다 `ddak/<이름>`만 봤다. `ddak/dev-1-web`만 있으면 dev-1을 고른 뒤 web에서 실패했다.
**수정**: 만들 것 목록(`plan`)을 이름 정하기와 실제 만들기가 함께 쓴다. 후보마다 실제로 만들 브랜치를 모두 검사한다.
**확인**: Rust 테스트 `derived_branches_are_checked_and_unique` — `ddak/dev-1-web`이 있으면 dev-2. 수정 전 코드에서 실패.

## 4. 항목 이름으로 만든 브랜치가 올바르거나 겹치지 않는다는 보장이 없음 (`worktrees.rs`) — 타당, 수정

**검증**: 실험. `git check-ref-format --branch`가 `ddak/x-z.lock`, `ddak/a.`를 거부한다. 소스상 한글 이름 둘은
`branch_safe`에서 둘 다 `group`이 된다.

**수정**
- `branch_safe`가 끝의 `.lock`·`.`도 없앤다 (`..`와 앞의 `.`·`-`는 원래 처리).
- 같은 저장소 안에서 브랜치가 겹치면 `-2`, `-3`을 붙인다.

**확인**
- Rust 테스트 `branch_names_are_valid`: 까다로운 이름 12개를 바꾼 결과를 `git check-ref-format`으로 확인. 수정 전 코드에서 실패.
- `derived_branches_are_checked_and_unique`: 같은 저장소의 worktree `web`, `z.lock`, `리뷰`, `한글`로 만들기 성공,
  브랜치 다섯이 모두 다름.

## 5. 끌기 취소·언마운트에서 window 리스너가 남음 (`Workspace.tsx`) — 타당, 수정

**검증**: 소스 확인 (정리는 pointerup에만 있었다). 자체 테스트로 재현: pointercancel 뒤의 움직임, 그리고 버튼을
떼고 pointerup 없이 온 움직임에도 탭 순서가 바뀌었다.

**수정**: 탭 끌기와 구분선 끌기가 `trackPointer` 하나를 쓴다. 끝나는 경우를 모두 같은 정리로 모았다.
- pointerup, pointercancel
- 버튼이 눌려 있지 않은 움직임 (창 밖에서 버튼을 떼면 pointerup이 오지 않는다)
- 언마운트 (효과 정리), 새 끌기 시작
- 끄는 중에 그 탭이 닫힘

**확인**: 자체 테스트 "pointercancel 뒤 움직임은 끌기가 아님", "버튼을 뗀 뒤 움직임은 끌기가 아님" (수정 전 코드에서
실패). 기존 끌기 테스트의 합성 움직임에 `buttons: 1`을 넣었다 (실제 끌기와 같게). 언마운트 정리는 소스로만 확인했다.

## 6. 다른 탭을 닫으면 넘겨 둔 스크롤이 되돌아옴 (`Workspace.tsx`) — 타당, 수정

**검증**: 소스 확인. 효과의 의존성이 `[s.active, s.tabs.length]`라서 탭 수가 바뀌면 `keep`이 초기화되고 `reveal()`을
불렀다. 자체 테스트로 재현: 휠로 200 넘긴 뒤 다른 탭을 닫으면 scrollLeft 0.

**수정**: 따라가기 상태를 ref(`follow`)로 효과 밖에 둔다. 활성 탭이 바뀔 때만 켜고 맞춘다. 탭 수가 바뀔 때는
ResizeObserver 관찰 대상만 다시 잡는다.

**확인**: 자체 테스트 "휠로 넘긴 뒤 다른 탭을 닫아도 그대로". 수정 전 코드에서 실패.

## 후속 리뷰: [P1] 직접 만들지 못한 브랜치를 Undo가 지움 (`worktrees.rs`) — 타당, 수정

**지적**: 1번 수정은 브랜치가 없음을 확인한 뒤 정리 목록에 넣고 `worktree add -b`를 실행한다. 확인 직후 다른
프로세스가 같은 브랜치를 만들면 `worktree add`는 이름 충돌로 실패하고, 정리가 그 외부 브랜치를 지운다.
처음 대응에서 "수 ms 틈이라 둔다"고 했던 부분이다. 빈도와 별개로 남의 작업을 강제로 지우므로 고쳐야 한다.

**검증**: 테스트로 재현. 테스트에서만 git 대신 감싼 스크립트를 쓰게 했다 (스레드별 `TEST_GIT`, PATH를 바꾸면
병렬 테스트에 번진다). 스크립트는 `ddak/dev-1`을 만드는 첫 명령 직전에 고유 커밋을 가리키는 외부 브랜치
`ddak/dev-1`을 만든다. 수정 전 코드에서 만들기 실패 후 외부 브랜치가 사라졌다.

**수정**
- 브랜치를 worktree와 따로 만든다: `git update-ref -m "ddak: work group" refs/heads/<브랜치> <HEAD 커밋> ""`.
  oldvalue `""`는 ref를 잠근 채 "없을 때만" 만든다 (git-update-ref 문서: 빈 oldvalue는 만들 ref가 없음을 확인,
  잠글 수 있고 oldvalue가 맞을 때만 수정). 성공한 브랜치만 정리 목록에 넣는다.
- 그 다음 `git worktree add <폴더> <브랜치>` (`-b` 없이).
- 정리할 때도 `update-ref -d refs/heads/<브랜치> <만든 커밋>`으로, 아직 우리가 만든 커밋을 가리킬 때만 지운다.
- 이름을 정할 때 하던 존재 확인은 빈 번호를 고르는 용도로만 남았다 (소유권 판단에는 쓰지 않는다).

**확인**: Rust 테스트 `never_deletes_branch_created_by_others` — 만들기는 "git" 오류로 실패, 외부 브랜치는 그대로
("external" 커밋). 수정 전 코드에서 실패. 1번 훅 실패 테스트와 나머지 worktree 테스트도 통과.
커밋 없는 저장소의 오류 문구가 `fatal: Needed a single revision`로 바뀌었다 (HEAD 확인에서 실패).
