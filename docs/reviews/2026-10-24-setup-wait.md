# 리뷰 대응: 작업그룹 준비 대기 · PTY 종료 (2026-10-24)

리뷰 범위: `0f95731` 이후 커밋 전 작업 트리 (준비 스크립트, 준비 대기, IUTF8, 탭 소수 픽셀).
지적 5건(P1 1, P2 4) 모두 타당, 수정. 검토 중 같은 영역에서 하나 더 찾아 고쳤다 (6번).
테스트마다 수정을 잠시 끄고 실패하는 것을 확인했다.

## 1. [P1] 거둔 자식의 PID에 신호를 보낼 수 있음 (`pty.rs`) — 타당, 수정

**검증**: 소스. portable-pty 0.9 `clone_killer()`는 `ProcessSignaller { pid }`를 돌려주고, `kill()`은 확인 없이
`libc::kill(pid, SIGHUP)`이다 (`lib.rs` 324행 부근). 기다리는 스레드가 `wait()`로 거둔 뒤에도 세션에 남아 있었다.
PID 재사용 자체는 재현하지 않았다 (리뷰어도 동일).

**수정**: 자식을 `Mutex<Proc { child, status }>` 하나에 두고, 거두기(`try_wait`)와 신호 보내기를 이 잠금 안에서만 한다.
신호는 같은 잠금 안에서 "아직 거두지 않음"을 확인한 뒤에만 보낸다. 거두지 않은 자식은 좀비라도 PID를 쥐고 있어
재사용될 수 없다. 기다리는 스레드는 `waitid(P_PID, WEXITED | WNOWAIT)`로 거두지 않고 끝나기만 기다린 뒤 잠금 안에서 거둔다.
macOS에서 `WNOWAIT` 동작을 실험으로 확인했다: 반환 뒤 `kill(pid, 0)` 성공(좀비), `waitpid` 뒤에는 ESRCH.

**확인**: Rust 테스트 `terminate_never_signals_reaped_pid`. "이미 끝났다"고 답하는 가짜 자식의 PID가 살아 있는
다른 프로세스(`sleep`)를 가리키게 해서 재사용을 흉내 낸다. 끝내기 뒤에도 그 프로세스가 살아 있어야 한다.
거둠 확인을 끄면 실패.

## 2. [P2] SIGHUP을 무시하는 준비 프로세스가 계속 돎 (`pty.rs`) — 타당, 수정

**검증**: 소스. `ProcessSignaller::kill`에는 `std::process::Child`용 `kill`의 SIGKILL 전환(SIGHUP 뒤 250ms 유예)이 없다.
실험: `zsh -l -i -c 'env … /bin/sh -c "trap \"\" HUP; sleep 3"'`를 PTY에서 띄우면 zsh가 exec로 바뀌어
`/bin/sh`가 세션·그룹 리더이고 `sleep`도 같은 그룹이다 (`ps`의 pgid).

**수정**: 끝내기 = 자식의 프로세스 그룹(`kill(-pid)`)에 SIGHUP, 250ms 안에 끝나지 않으면 SIGKILL. 매 신호는 1번의
잠금 확인 뒤에 보낸다 (그룹 리더를 거두지 않았으니 그룹 ID도 재사용되지 않는다). 유예가 있어 `pty_kill`은
별도 스레드에서 끝내고, 그동안 터미널(master)을 쥐고 있는다.

**확인**: Rust 테스트 `terminate_stops_hup_ignoring_script` (`trap '' HUP` + `echo tick` 반복): 끝내기 뒤 출력이
늘지 않고 종료 코드 없음(시그널). SIGKILL 단계를 끄면 "끝낸 뒤에도 출력이 이어짐"으로 실패.

## 3. [P2] 생성 응답보다 먼저 온 종료를 버림 (`Terminal.tsx`) — 타당, 수정

**검증**: 소스. 종료는 전역 이벤트(`pty-exit`)였고, 프론트는 `pty_spawn` 응답으로 받은 id와 맞을 때만 처리했다.
Rust는 응답 전에 스레드를 시작하므로 짧은 명령이면 순서가 뒤집힌다. 리스너 등록(`listen`)도 비동기라 같은 틈이 있다.

**수정**: 종료를 출력과 같은 채널로 보낸다 (`{"exit": 코드}`, 출력은 바이트). Tauri 채널은 번호 순서대로 전달하고
(`@tauri-apps/api/core.js` Channel), 프론트가 spawn을 부르기 전에 만들어 두므로 id가 필요 없다. 전역 이벤트는 없앴다.

**확인**: 자체 테스트. 개발 빌드 전용 `devHooks.spawnDelay`로 생성 응답을 1.5초 늦춘 채 "다시 준비"를 누른다
(스크립트는 바로 끝남). 세션이 떠야 한다. 프론트에서 id 확인을 되살리면 "준비 성공 뒤 세션" 시간 초과로 실패.

## 4. [P2] PTY 생성 실패가 준비 실패로 가지 않음 (`Terminal.tsx`) — 타당, 수정

**검증**: 소스. 생성 오류는 터미널에 쓰기만 했고 종료도 오지 않아 준비가 "실행 중"으로 남았다.

**수정**: `Terminal`에 `onSpawnError`를 두고, 준비 창이면 준비 실패("준비를 시작하지 못함")로 바꿔 다시 준비 / 그래도
시작을 보인다.

**확인**: 자체 테스트. 준비를 중단한 뒤 작업그룹 폴더를 옮겨 두고 다시 준비 → "Could not start the setup", 터미널에
"no such folder", 스크립트 출력 없음. 폴더를 되돌리고 그래도 시작 → 세션이 뜸. 알림을 끄면 실패.

## 5. [P2] 준비 스크립트 읽기 오류를 "없음"으로 봄 (`setup.rs`) — 타당, 방식은 다르게 수정

**검증**: 소스. `read_to_string(..).ok()?`가 모든 오류와 UTF-8이 아닌 내용을 None으로 바꿨다.

**판단**: 목표(준비 없이 CLI를 띄우지 않기)는 동의. 다만 만들기를 오류로 막는 대신 그 스크립트를 그대로 돌린다:
`/bin/sh`가 준비 창에 오류를 보이고 실패해서 (디렉터리면 "is a directory", 종료 코드 126) 세션은 기다리고,
사용자가 파일을 고친 뒤 다시 준비를 누를 수 있다. 만들기를 막으면 이미 만든 worktree를 되돌려야 하고 다시 준비 흐름도 없다.

**수정**: 없는 파일(NotFound)만 "준비 없음". 내용은 바이트로 읽어 명령이 있는지 본다 (UTF-8이 아니어도 sh는 실행한다).
그 밖의 읽기 오류는 그 경로를 돌린다. 스크립트 경로 자체를 못 구하면 (`script_path`) 만들기 전에 오류로 끝낸다.

**확인**: Rust 테스트 `unreadable_script_still_runs` (없음 → None, 주석뿐 → None, Latin-1 내용·디렉터리 → 실행).
옛 읽기로 되돌리면 실패.

## 6. (추가 발견) 작업 폴더가 없으면 홈 폴더에서 띄움 (`pty.rs`) — 수정

**검증**: 소스. portable-pty `CommandBuilder::as_command`는 cwd가 디렉터리가 아니면 오류 없이 홈 폴더를 쓴다
(`cmdbuilder.rs` 498행 부근). 4번의 "폴더가 사라지면 생성 실패"는 실제로는 실패가 아니라 준비 스크립트나 claude가
홈 폴더에서 도는 것이었다.

**수정**: 띄우기 전에 작업 폴더가 디렉터리인지 보고 아니면 오류 (`<폴더>: no such folder`). 확인과 띄우기 사이에
폴더가 사라지는 틈은 남는다.

**확인**: Rust 테스트 `missing_cwd_fails`, 자체 테스트 4번 항목. 확인을 끄면 실패.

## 후속 리뷰: [P2] 부모가 먼저 끝나면 SIGHUP을 무시하는 자식이 남음 (`pty.rs`) — 타당, 수정

**지적**: 2번 수정은 SIGHUP 뒤 그룹 리더(부모)가 끝났으면 바로 돌아와 그룹에 SIGKILL을 보내지 않았다.
부모는 기본 처리로 끝나고 자식만 `trap '' HUP`이면 자식이 남는다.

**검증**: 테스트로 재현. `(trap '' HUP; while :; do echo t >> <로그>; sleep 0.05; done) & wait`. 끝내기 뒤에도
로그가 계속 늘었다. 부모가 끝나면 터미널이 끊겨 출력으로는 보이지 않아 파일로 본다. 기존 테스트는 부모도 무시해서 놓쳤다.

**수정**: 거두기를 끝내기로 옮겼다. 기다리는 스레드는 거두지 않고(`waitid WNOWAIT`) 종료 코드를 siginfo에서 읽는다
(`CLD_EXITED`면 `si_status`, 시그널이면 없음). 끝내기는 그룹에 SIGHUP을 보낸다. 0.25초 안에 그룹이 비지 않으면
(`kill(-pgid, 0)`) 그룹에 SIGKILL을 보내고, 리더에게도 SIGKILL을 보낸 뒤 거둔다.
리더를 거두기 전까지는 좀비가 PID를 쥐고 있다. 그래서 리더가 먼저 끝났어도 그 번호로 새 프로세스나 새 그룹이 생기지
않는다. 이렇게 1번(P1)의 안전성을 유지한 채 남은 그룹을 정리한다. 터미널을 닫기 전까지 끝난 자식이 좀비 하나로
남는다 (준비 창처럼 끝난 뒤에도 열어 두는 창).

**확인**
- Rust 테스트 `terminate_stops_hup_ignoring_child_after_parent_exits`: 그룹 SIGKILL을 끄면 실패.
- Rust 테스트 `child_stays_unreaped_until_terminate`: 끝난 자식이 끝내기 전까지 좀비로 남고 끝내기 뒤 사라진다.
  기다리는 스레드에서 거두게 하면 실패.
- P1 테스트는 "이미 거둠" 표시가 있는 자식에게 두 번째 끝내기가 신호를 보내지 않는지로 바꿨다.

## 그 밖의 바뀐 동작

- 종료 알림은 자식이 끝난 시점 기준이다. 출력이 끝나기를 최대 0.5초 기다린 뒤 알린다. 전에는 출력이 끝나야(모든
  프로세스가 터미널을 놓아야) 알려서, 백그라운드 손자가 터미널을 쥐고 있으면 준비가 끝나지 않았다.
