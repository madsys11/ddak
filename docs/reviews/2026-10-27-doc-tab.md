# 문서 탭: 마크다운을 앱 안에서 보기 (2026-10-27)

**요청** (사용자, 폰에서): 마크다운 파일을 앱 안에서 볼 수 있으면 좋겠다. 제안(#198) "추천대로"(#199):
터미널 .md ⌘+클릭은 앱 안 문서 탭으로, 문서는 일반 탭으로, 폰 보기는 이번 범위에서 뺌.

**제안과 다르게 정한 것**:
- 제안에 "다른 탭처럼 분할"이라고 적었으나 Git Graph 탭과 같이 분할·세션 추가는 없다 (터미널이 없는 탭). 닫기·이름·순서·
  저장·복원은 같다.
- 문서 안의 다른 .md 링크는 "그 탭에서"가 아니라 문서 탭으로 연다 (열려 있으면 그 탭, 아니면 새 탭). 뒤로 가기가 없어
  같은 탭에서 바꾸면 보던 문서를 잃는다.
- markdown-it 버전: 15.0.3 (2026-10-16, 11일 전). 2주가 넘은 15.0.2에는 npm audit high 2건(GHSA-vfgh-jcmw-g37q 인라인 HTML,
  html을 끄면 해당 없음 / GHSA-gfr2-rv44-r23c 여러 줄 참조 정의의 이차 시간, 기본 설정에서 해당)이 있어 고친 판을 썼다.
  의존성은 entities·linkify-it·mdurl·punycode.js·uc.micro (모두 markdown-it 쪽).

**구현** (spec "문서 탭 (마크다운)", 터미널 링크, 파일 트리):
- `src/docs.ts`: 문서 경로 판정, 열기 요청(창 이벤트 → App), 문서 안 주소 해석(`resolveHref`), 그리기(`renderMarkdown`:
  `html: false`, 제목 앵커, 체크박스 토큰).
- `src/DocView.tsx`: 읽기(`fs_read_text`), 폴더 감시로 다시 읽기, 그림(`fs_read_image` → data:, 웹 그림은 링크로), 링크 클릭
  (웹뷰 이동은 늘 막음).
- `Workspace.tsx`: `openDoc`(파일마다 한 탭, 실제 경로), 탭 아이콘·제목·메뉴(기본 앱으로 열기), 분할·세션 추가 막기

  읽은 뒤 연다). `FileTree.tsx`·`Sidebar.tsx`: 더블클릭·메뉴, 트리의 프로젝트(`ProjectContext`).
- `terminalLinks.ts`: ⌘+클릭한 경로·`file://`가 마크다운이면 문서 탭.
- `fs.rs`: `fs_read_text`(5 MB), `fs_read_image`(형식은 확장자로, 20 MB). 오류 코드 missing·tooLarge·notImage·io.

## 리뷰 1차 (#201)

**R1 [P1] 웹 그림 막기가 화면에 넣은 뒤라 바깥 요청을 막지 못함 — 타당.** `dangerouslySetInnerHTML`로 `<img src="https://…">`를
넣는 순간 WebKit이 불러오기 시작하고, 효과(useEffect)는 그 뒤에 돈다. 로컬 그림도 원래 상대 주소가 잠깐 `src`에 들어갔다.
수정: markdown-it의 그림 규칙을 바꿔 만드는 HTML에 주소를 넣지 않는다. `data:image/`만 `src`, 웹 그림은 링크 글자
(`[그림: 이름]`), 로컬 그림은 `data-src`에 두고 DocView가 Rust로 읽어 data: 주소를 넣는다.
확인: docView "그림은 만든 HTML에 바깥·로컬 주소 없이" (`renderMarkdown` 결과에 data: 아닌 `src=`가 없음), 그림 규칙을 끄면 실패.
WebKit의 실제 네트워크 요청을 세는 검사는 아니다 (만든 HTML에 주소가 없으면 요청할 대상이 없다).

**R2 [P2] 다른 문서의 #제목 링크에서 앵커를 버림 — 타당.** 수정: 열기 요청에 `anchor`, App → Workspace(`jump`) → DocView가
그 제목이 그려진 뒤 한 번 스크롤. 확인: docView "다른 문서의 #제목 링크는 그 문서를 열고 그 제목으로" (이미 열린 문서, 제목이
문서 위쪽에 옴). 앵커 전달을 빼면 실패.

**R3 [P2] 터미널의 file:// 주소에서 호스트를 버림 — 타당.** 수정: `docPathOf`가 호스트가 비었거나 localhost일 때만 경로로
보고, 아니면 문서 탭이 아니라 `open_link`로 넘긴다 (Rust가 거절). 확인: docView 검사에 `file://other/…` → 문서 아님, localhost·
`%20` 풀기. 호스트 검사를 빼면 `/p/a.md`가 나와 실패 (Node로 확인).

Rust 117개 통과, tsc 통과, docView 9개 통과.

## 재리뷰 1회 (#203)

R1·R2·R3 해결 확인, 수정 범위에서 새 차단 문제 없음.
