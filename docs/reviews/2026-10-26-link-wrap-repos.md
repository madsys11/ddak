# 터미널 링크: 잘린 긴 경로 · 저장소 기준 경로 (2026-10-26)

**요청**: 설치본에서 링크 열기를 써 보니 claude 창의 두 경우가 열리지 않았다. 둘 다 진행 요청.
1. claude가 저장소 안 경로(`docs/spec.md`)로 말하는데, 세션 폴더가 저장소들의 위 폴더(`dev-review-9/`, 저장소는 `ddak/`)라 없는 경로였다.
2. 창 폭보다 긴 경로(scratchpad html, 142자)를 claude가 두 줄로 잘라 그려서 열리지 않았다.

**확인**: 짧은 절대 경로와 세션 폴더 기준 경로(`ddak/docs/spec.md`, 파란 글씨 포함)는 claude 창에서 열린다(사용자 확인). claude를 pty로
띄워 출력을 받아 보니 마크다운 코드(파란 글씨)는 색만 바꾼 평문이고 (`\x1b[12G\x1b[38;2;87;105;247mddak/docs/spec.md\x1b[39m에`),
줄은 claude가 스스로 잘라 커서 이동으로 그린다 (xterm의 넘친 줄 `isWrapped`가 아니다).

**구현**:
- 1 (`links.rs` resolve): 프로그램의 현재 폴더·창의 폴더에 없으면 그 바로 아래 git 저장소(`.git` 폴더 또는 worktree의 `.git` 파일,
  이름 순 32개)마다 본다. 한 곳에서만 찾아질 때만 (같은 파일을 가리키는 것은 하나로). 여러 곳이면 링크가 아니다.
- 2 (`terminalLinks.ts` joinedAround): 한 줄의 마지막 낱말과 다음 줄의 첫 낱말(들여쓰기 뒤)을 이어 붙인다. 다음 줄이 그 낱말 하나뿐이면
  그다음 줄로 더 잇는다 (앞뒤 3줄까지). 이음을 지나는 경로 후보만 쓰고 실제로 있어야 링크. URL은 확인할 수 없어 잇지 않는다.
  같은 칸에서 시작하는 후보 하나만 남기던 규칙을 "다른 링크 안에 든 링크는 뺀다"로 바꿨다 (이어 붙인 경로가 있으면 앞 줄의 조각
  `a/`가 같은 칸에서 시작해 이어 붙인 것을 가렸다. 조사를 붙인 것과 뗀 것도 같은 규칙으로 긴 것이 남는다).

**확인**: Rust resolves_relative_paths_against_each_base에 저장소 한 곳(`.git` 폴더)·worktree(`.git` 파일)·저장소 아닌 폴더·
두 저장소(모름)·폴더 자체가 먼저 추가. selftest terminalLinkWrap에 20열 `  x a/` + `  한.md에 끝` (앞 조각 `a/`도 있는 폴더):
두 줄 모두에서 `a/한.md` 하나, 범위 (5,1)–(7,2). terminalLinks에 셸이 cd 한 폴더 아래 `repo/.git`의 `docs/guide.md`를 ⌘ 클릭으로
연다. 잇기·저장소 찾기를 끄면 각 검사와 Rust 테스트가 실패.

## 리뷰 1차 (#131)

**R1 [P2] 경로가 끝난 줄 뒤에 다른 문장이 오면 경로를 놓침 — 타당.** 다음 줄이 낱말 하나(`한.md`)뿐이라 그다음 줄(`Next step`, `❯`)까지
이어 붙인 `a/한.mdNext` 하나만 냈다. 새 검사로 재현: 첫 줄은 `a/` 폴더 링크, 둘째 줄은 링크 없음. 자체 테스트의 `한.md에 끝`은 같은
줄의 `끝`에서 멈춰 이 경우를 잡지 못했다. 수정: 이을 때마다 그때까지의 글자를 후보로 낸다 (있는 것 중 가장 긴 것이 포함 규칙으로
남는다). 확인: terminalLinkWrap에 `  x a/` + `  한.md` + `Next step` / `❯` 두 경우 추가 (두 줄 모두 `a/한.md`). 끝에서만 내도록 되돌리면 실패.

**R2 [P2] 저장소가 32개를 넘으면 모호한 경로를 유일하다고 봄 — 타당.** 이름 순으로 자른 뒤 유일성을 봐서 33번째 저장소의 같은 경로를
보지 못했다. 수정: 자르지 않고 모든 저장소를 보고, 서로 다른 두 곳에서 찾으면 바로 모름. 저장소가 256개(`MAX_REPOS`)를 넘으면 모두
보지 않고 모름. 같은 실제 대상을 가리키는 저장소 링크는 한 곳. 확인: Rust 테스트에 저장소 40개 중 r00·r32에 같은 경로(모름), 한 곳에만
있는 경로(찾음), 257개 넘으면 모름, 같은 저장소를 가리키는 링크(한 곳) 추가. 32개로 자르던 동작으로 되돌리면 r00을 열어 실패.

**R3 [P3] 저장소 목록을 후보마다 다시 구함 — 타당, 반영.** `Bases`가 한 `link_targets` 호출에서 저장소 목록을 처음 필요할 때 한 번만
구하고 (`OnceCell`), 같은 폴더(프로그램의 현재 폴더 = 창의 폴더)는 한 번만 본다. 두 곳을 찾으면 바로 끝낸다.
