# 작업 기록: 사용자 알림 (2026-10-25)

사용자 요청: peon(응답마다 울림)을 대신해, 사용자 개입이 필요하거나 작업이 커밋 대기까지 갔을 때만 확실히 알림을 받고 싶다
(다른 프로젝트를 보고 있어도). 1단계(채팅 기반 알림)와 2단계(claude 권한 확인)를 함께 하기로 했다. 리뷰 대응은 아래에 덧붙인다.

## 판단

- 무엇에 울릴지: 규약상 세션은 질문·결정 요청·막힘·완료 보고를 `@user`로 보낸다. 그래서 "세션이 사용자에게 보낸 채팅
  메시지"를 기준으로 하고, 규약 2번에 "결정·승인·입력이 필요하거나 커밋 준비가 되면 반드시 @user"를 명시했다.
  앱이 아는 자동 깨우기 멈춤도 알린다.
- 빈틈: claude가 권한 확인을 띄우면 채팅에 쓸 수 없다. claude `--settings`의 `PermissionRequest` 훅으로 ddak 주소에 알린다.
  실험 (claude 2.1.310, `-p`): 권한이 필요한 Write에서 훅이 울렸고 (POST 수신), 권한이 필요 없는 `date`에서는 울리지 않았다.
  대화형 화면의 권한 확인에서도 같은 훅이 울리는지는 설치 뒤 직접 확인한다.
- 보내는 곳: macOS 알림 센터 (UNUserNotificationCenter, objc2-user-notifications, 캐시에 있음). 번들 앱에서만 쓸 수 있어
  개발·자체 테스트에서는 기록만 한다. 알림 결정(보고 있으면 생략)은 Rust가 한다: 창이 가려지면 웹뷰가 멈출 수 있어서 프론트에
  맡기지 않았다.

## 확인

- Rust: notify skips_when_watching, chat wake_limit (멈춤 알림 한 번), mcp_over_http (/attention/<토큰> 204·404·405·403),
  groups default_is_valid (claude --settings 훅에 {attention}). 79개 통과.
- selftest addSession: 세션이 @user로 보내면 알림 기록·사이드바 배지 1·Dock 배지 1, 열면 0. 창이 앞 + 채팅을 보고 있으면 알림
  없음. {attention}으로 보내면 "origin/attn is waiting for your permission". 6개 제한에 걸리면 멈춤 알림.
- 알림 경로를 끄면 (메시지·멈춤·attention 알림, Dock 배지) 위 검사가 실패한다.
- 한계: 실제 알림 센터 배너·소리·권한 묻기와 대화형 claude의 권한 확인 훅은 설치 뒤 직접 확인해야 한다.

## 함께 넣은 것 (사용자 결정): 터미널 입력도 자동 깨우기를 다시 센다

리뷰 요청이 6개 제한에 걸려 리뷰어가 깨어나지 않았다. 루프가 아니라 정상 흐름이었다 (리뷰 한 번 = 요청·결과 2개). 사용자는
지시를 터미널에 직접 쓰므로 채팅 기준 셈이 초기화되지 않았다. 사용자가 그 작업그룹 세션의 터미널에 입력하면 재개와 같이 다시
센다 (`Chats::user_input`). 확인: Rust wake_limit (다른 그룹의 입력으로는 안 풀림, 셈이 없으면 아무것도 안 함, 끄면 실패),
selftest "그 작업그룹 세션의 터미널에 사용자가 입력하면 다시 센다".

확인하지 못한 것: 자체 테스트에서 합성 키 한 글자 "u"만 친 경우 `pty_write`가 사용자 입력이 아님(user=false)으로 왔다
("abc"는 사용자 입력으로 왔다). 원인은 찾지 못했고 실제 키보드에서도 그런지는 모른다. 검사는 "abc"로 친다.

## 리뷰 (채팅 #76)

### R1 샌드박스 네트워크 승인에서는 알림이 오지 않음 (P2) — 타당, 수정

**검증**: 공식 훅 문서 — "Claude Code doesn't run PermissionRequest hooks for a sandboxed command's network request. To get
a signal for that prompt, use the `permission_prompt` notification type." `permission_prompt`는 확인이 약 6초 답 없이 떠 있을
때 울린다. 실험 (claude 2.1.310 대화형, 사용자 설정 없이 `--permission-mode default`, `mkdir` 권한 확인을 띄우고 기다림):
PermissionRequest 18:15:50, Notification(permission_prompt) 18:15:56에 각각 울렸다.
**수정**: 기본 claude 인자의 훅을 `Notification`(matcher `permission_prompt`) 하나로 바꿨다 (두 훅을 함께 두면 두 번 울린다).
바로 답하면 울리지 않는 것도 "보고 있지 않을 때만" 알리는 목적에 맞다. **확인**: groups default_is_valid (PermissionRequest
없음, matcher permission_prompt).

### R2 다른 프로젝트에 가려진 열린 채팅을 읽은 것으로 처리함 (P2) — 타당, 수정

**검증**: 소스. 읽음 처리가 `open`만 봐서, 열어 둔 채 다른 프로젝트로 가면 숨은 패널이 메시지를 읽은 것으로 처리했다.
**수정**: `ChatPanel`에 `watching`(열림 + 그 프로젝트가 보임 + 창이 앞에 있음, App이 창 focus/blur로 안다)을 넘겨 그때만 읽은
것으로 친다. 보게 되면 지운다. **확인**: selftest "채팅을 열어 둬도 창이 뒤에 있거나 다른 프로젝트에 있으면 배지에 세고,
보게 되면 지움" (blur 중에 온 메시지, 다른 프로젝트로 옮긴 사이 2초 뒤 온 메시지). `watching`을 `open`으로 되돌리면 실패.

## 전체 실행에서 고친 것

- 알림을 화면 갱신·깨우기보다 먼저 보낸다 (`chat.rs` install): 깨우기가 터미널 잠금을 기다리는 동안 프론트가 먼저 기록을
  읽었다. 테스트도 기록이 생길 때까지 모아 가며 기다린다.
- 끌어 놓기 검사: 셸 입력 줄은 길면 다시 그려져 화면에서 그대로 읽기 어려워, 놓은 경로를 `printf`로 돌려 출력으로 본다.
- 채팅 패널 검사 시작에 창 focus를 알린다: R2 이후 읽음은 창이 앞에 있어야 해서, 테스트 창에 포커스가 없으면 첫 메시지가
  읽지 않은 채 남았다.
- 확인: 전체 scripts/selftest.sh 355개 통과 (146초).

## 설치 뒤: 배지는 바뀌는데 알림이 뜨지 않음 — 원인, 수정

**보고**: 다른 창에 포커스를 두니 배지는 보였지만 알림 배너가 뜨지 않았다.

**확인**: macOS 알림 설정(`~/Library/Preferences/com.apple.ncprefs.plist`, 앱 106개)에 ddak이 없었다 — 권한 요청이 등록되지
않았다. 설치된 앱의 서명: `Identifier=ddak-b6aa2ee705d5c985`, `flags=adhoc,linker-signed`, `Info.plist=not bound`. 링커가 실행
파일만 서명해서 서명 식별자가 앱 식별자가 아니고 번들 정보도 묶이지 않았다. 알림 센터는 서명으로 앱을 알아본다.

**수정**: `tauri.conf.json` `bundle.macOS.signingIdentity: "-"` (번들 전체 임시 서명). 빌드 결과:
`Identifier=io.github.madsys11.ddak`, `Info.plist entries=14`, `codesign --verify --deep --strict` 통과 (hardened runtime이 붙는다).
Rust `bundle_is_signed_ad_hoc`이 설정을 본다. 설치 뒤 알림 권한을 묻고 ncprefs에 등록되는지 직접 확인한다.
서명 식별자가 바뀌므로 macOS가 예전 앱에 준 다른 권한(폴더 접근 등)을 다시 물을 수 있다.
