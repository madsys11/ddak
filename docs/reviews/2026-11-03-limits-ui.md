# 협업 제한을 화면에서 바꾸기 (2026-11-03, 계획)

## 요청

사용자: 리뷰 제한(리뷰 1회 + 재리뷰 최대 2회)과 대화 제한(세션끼리 사용자 없이 10개)을 UI에서 바꿀 수 있게.

지금:
- 재리뷰 횟수: 코드가 막지 않는다. 기본 작업그룹(dev-review)의 규약(rules) (4)번 문장 "at most two re-reviews … after the second
  re-review"를 세션이 지킨다. 규약은 `groups.json`에 글로 들어 있고 (기본 설정을 처음 쓸 때 `groups.rs` RULES), 프론트가 세션을 만들
  때 역할과 합쳐 `{prompt}`로 넣는다 (`useGroups.ts` promptOf).
- 대화 제한: `chat.rs` 상수 `WAKE_LIMIT` = 10. 데스크톱 패널(`ChatPanel.tsx`)과 폰(`MobileApp.tsx`)의 멈춤 문구도 각자 상수 10.

## 설계

### 저장

- 앱 데이터의 `limits.json` (`src-tauri/src/limits.rs`, Rust가 읽고 쓴다): `{"wakeLimit": 10, "reReviews": 2}`.
  - 없거나 읽지 못하거나 값이 범위 밖이면 그 값은 기본 (10, 2). 범위: wakeLimit 1–100, reReviews 0–5.
  - 쓰기는 옆에 쓰고 옮긴다 (`workspace.rs` save와 같게).
- `groups.json`에 넣지 않는 이유: 사용자가 직접 고치는 파일이고 앱은 다시 쓰지 않기로 했다 (2026-10-31 결정, 읽기·저장 겹침).
- 명령: `limits_get` → 값, `limits_set(wakeLimit, reReviews)` → 범위를 확인하고 쓴 뒤 이벤트 `limits`.

### 대화 제한 (wakeLimit)

- `chat.rs`: 상수 대신 `Chats`가 지금 값을 갖는다 (`set_wake_limit`). 앱을 켤 때 `limits.json`에서, 바꾸면 `limits_set`이 넣는다.
  셈·보류·멈춤 판정(`post`, `paused`)과 보낸 세션에 주는 안내 문구, 멈춤 알림 문구가 지금 값을 쓴다.
- 값이 실제로 바뀌었을 때만: 모든 프로젝트·작업그룹의 셈을 0부터 다시 하고 보류된 알림을 (받는 사람, 보낸 사람)마다 한 번
  보낸다 (사용자의 재개와 같다). 재리뷰 횟수만 바꿈, 같은 값 저장, 취소, 저장 실패(파일을 쓰지 못함)는 셈·보류를 그대로 둔다.
  이유: 낮추면 이미 넘은 그룹이 알림 없이 멈추고, 높이면 보류된 알림이 남은 채 멈춤 표시만 사라지는 경우가 생긴다.
  사용자가 바꾼 것이라 재개로 본다.
  - 잠금: 값 갱신과 셈 초기화·보류 꺼내기는 `post`·`paused`와 같은 잠금 안에서, 깨우기와 변경 알림(`Change::Released`,
    `Change::Limits` → `chat-limit`와 폰 `members` 이벤트)은 기존 `resume`처럼 잠금 밖에서. 프로젝트마다 보류분을 겹치지 않게 모은다.
  - `limits_set` 순서: 범위 확인 → 파일 쓰기 → (성공했고 wakeLimit이 바뀌었으면) `Chats`에 넣기. 파일을 못 쓰면 오류를 돌려주고
    아무것도 바꾸지 않는다.
- 데스크톱 패널의 멈춤 문구: `limits_get`과 `limits` 이벤트로 지금 값.
- 폰: `GET …/members` 응답에 `wakeLimit`을 더한다 (선택 필드라 API 버전은 그대로). 없으면 (예전 ddak) 10.

### 재리뷰 횟수 (reReviews)

- 기본 규약 (4)번을 자리표시자로 바꾼다: "A change gets one review and at most {reReviews} re-reviews. … If blocking findings remain
  once the re-reviews are used up, stop the exchange and report once to the user …". 숫자는 아라비아 숫자로 넣는다 (0도 문장이 됨).
- 프론트 `promptOf`가 규약의 `{reReviews}`를 지금 값으로 바꾼다 (역할에는 쓰지 않는다). 다른 글은 건드리지 않는다.
- 읽는 순서: App은 지금 작업그룹 설정을 읽은 뒤에 Workspace를 연다 (`groupsReady`). 협업 제한도 읽은 뒤에 열어 (못 읽으면 기본값)
  처음 만드는 세션이 기본 횟수로 만들어지지 않게 한다. 값이 바뀌면(`limits` 이벤트) 그 뒤 만드는 세션부터.
- 이미 있는 `groups.json`: 규약이 이전 기본 RULES와 글자 그대로 같은 그룹만 읽을 때 새 기본(자리표시자)으로 바꾼다 (메모리에서만,
  `groups.rs` upgrade와 같은 방식). 고친 규약은 그대로 두고, 그 그룹에는 재리뷰 횟수가 적용되지 않는다.
- 저장된 탭: 세션의 `prompt`는 만들 때 정한 글이 저장되어 복원된다. 바꾼 횟수는 새로 만든 세션부터 (지금 떠 있는 세션과 복원한
  세션은 처음 받은 규약). 화면에 그렇게 적는다.

### 화면

- 앱 메뉴에 "협업 제한…"(`limits`, "작업그룹 설정…" 아래). 누르면 창 (`src/LimitsDialog.tsx`, 모바일 연결 창과 같은 방식):
  - "세션끼리 사용자 없이 주고받을 메시지 수" (1–100), 설명: 넘으면 저장만 하고 깨우지 않음. 바꾸면 모든 프로젝트·작업그룹을
    다시 세고, 멈춘 작업그룹의 보류된 알림을 보내 자동 깨우기를 재개한다 (리뷰 R2).
  - "재리뷰 최대 횟수" (0–5), 설명: 작업그룹 규약에 들어감, 새로 띄운 세션부터. 규약에 `{reReviews}`가 없는 그룹(직접 고친 규약)이
    있으면 그 이름을 보이고 그 그룹에는 적용되지 않는다고 알린다.
  - 저장 / 취소. 범위 밖이면 저장 단추를 막고 이유를 보인다.
- 문구는 i18n 키. 폰에는 설정 화면을 두지 않는다 (요청이 맥/PC UI).

## 안 바꾸는 것

- 이미 떠 있는 세션의 규약 (세션 프롬프트는 시작할 때 정해짐).
- 규약의 다른 문장, 사용자가 고친 규약.

## 시험

- Rust: `limits.rs` 읽기·쓰기 (없음, 깨짐, 범위 밖 → 기본), `chat.rs` 제한을 바꾸면 그 값으로 멈추고 바꿀 때 셈을 다시 하며 보류분을
  알림 (기존 `wake_limit_per_work_group`을 지금 값으로), `groups.rs` 이전 기본 규약만 새 규약으로 (고친 규약은 그대로).
- 프론트 단위: `promptOf`가 규약의 `{reReviews}`만 바꿈, 역할은 그대로.
- 메뉴 (리뷰 R1): 맥은 `clickMenu`로 실제 메뉴를 눌러 창이 열리는지 본다. Windows는 `clickMenu`가 없어서 `selftest_menu`로 항목이
  있는지 보고, 창 시험은 메뉴 이벤트로 연다 (이건 창 시험이지 메뉴 연결 시험이 아니다). `menu.rs` run의 허용 목록에 넣는 것은
  맥 clickMenu 검사가 본다. Windows의 실제 클릭은 직접 확인한다.
- 자체 테스트 `limitsDialog`: 창을 열어 값을 바꾸고 저장 → `limits_get`, 채팅 패널 멈춤 문구의 수, 새로 만든 세션의 `{prompt}`에
  들어간 횟수, 범위 밖 입력 막힘, 고친 규약 그룹 알림, 취소하면 그대로.
- 다시 켜기 (`restart` 시나리오): 저장한 재리뷰 횟수로 앱을 다시 켜 처음 만드는 세션의 `{prompt}`에 그 수가 들어감.
- Rust `chat.rs`: wakeLimit이 바뀔 때만 셈 초기화·보류 알림 (같은 값·재리뷰만 바꿈은 그대로), 여러 프로젝트의 보류분이 겹치지 않음,
  멈춤이 풀리고 `Change::Limits`가 프로젝트마다 나감.
- 폰: `mobileChatUnit`에 members의 `wakeLimit`이 멈춤 문구에 쓰이는지 (없으면 10), 열린 화면이 members 이벤트로 새 값과 풀린
  멈춤을 다시 받는지.
- 기존 testChatPanel(깨우기 제한)은 상수 대신 지금 값으로 센다.
- spec.md "작업그룹 협업 규약"·"자동 깨우기 제한"·작업그룹 설정 절을 고친다.

## 구현 (사용자 승인 뒤)

- Rust: `limits.rs`(읽기·쓰기·`limits_get`·`limits_set`), `chat.rs`(상수 → `Inner.wake_limit`, `set_wake_limit`, `Change::Paused`에
  그때의 수, MCP 안내 문구), 앱을 켤 때 저장한 값을 넣음. `groups.rs`(규약 4번 `{reReviews}`, 이전 기본 규약만 메모리에서 바꿈).
  `menu.rs`(앱 메뉴 "협업 제한…", run 허용 목록), `mobile.rs`(members에 `wakeLimit`).
- 프론트: `src/limits.ts`(저장소, `fillRules`), `useGroups.ts` promptOf, `src/LimitsDialog.tsx`(`fixedRuleGroups`), App(제한을
  읽은 뒤 Workspace, 메뉴 → 창), ChatPanel·폰 멈춤 문구. i18n `menu.limits`·`limits.*`.
- 자체 테스트 main 시나리오는 앱 데이터에 `limits.json`(재리뷰 3)을 넣고 띄운다 (`scripts/selftest.sh`).
