## 1. [P1] 커밋 상세를 읽다가 파일을 덮어쓸 수 있음 — 타당, 수정

**검증**: 소스. `git log`를 제어 문자(US·RS)로 나눠 읽어서, 커밋 제목에 그 문자를 넣으면 행이 어긋났다. 그렇게 만든 가짜
"SHA"(`--output=README.md`)를 상세에서 그대로 `git show`·`diff-tree`의 인자로 넘겼다. 뒤에 붙인 `--`는 리비전과 경로를
나눌 뿐이라, 그 앞의 `--output=…`은 옵션으로 해석된다. 실험(git 2.39.5): `--end-of-options` 뒤에 두면 그 값은 옵션이 되지
않고(오류로 끝남) 파일이 생기지 않는다.

**수정** (두 겹)
- 읽기:
  - `git log -z --format=%H %P%x00%an%x00%at%x00%s`로 NUL을 나눠 읽는다.
  - SHA·부모가 16진수 40·64자가 아니거나 시각이 숫자가 아니면 오류로 멈춘다 (어긋나게 읽지 않음).
  - 상세(`git show`)도 NUL로 읽고, 돌아온 SHA가 요청한 SHA와 같은지 본다.
- 넘기기: git에 넘기는 SHA는 16진수만 받고(`is_sha`), 리비전 앞에 `--end-of-options`를 둔다 (log, show, diff-tree).
- 출력을 자르지 않고 그대로 받는 실행 함수(`raw`)를 따로 둔다 (`git()`은 앞뒤 공백을 자른다).

**확인**: Rust `hostile_messages_names_and_nested_tags`.
- 제목이 `x␞--output=README.md␟␟a␟0␟y␞`인 커밋이 정확히 한 행으로, 제목 그대로 읽힌다.
- `detail("--output=README.md")`는 거부되고 README는 그대로다.
- 고치기 전 `git.rs`에 이 테스트를 붙이면 첫 단언(가짜 행)에서 실패한다.
- SHA 검사와 `--end-of-options`를 함께 끄면 README가 덮어써져 실패한다 (한쪽만 끄면 다른 쪽이 막는다).

## 2. [P2] 다른 커밋을 골라도 이전 상세가 남음 — 타당, 수정

**검증**: 소스. 선택이 바뀌어도 이전 상세를 비우지 않았고, 응답이 오기 전이나 실패하면 이전 커밋의 상세가 남았다. 실패는
상세가 아니라 위쪽 오류 줄로만 갔다.

**수정**
- 선택이 바뀌면 상세와 상세 오류를 바로 비운다.
- 응답은 지금 고른 SHA와 같을 때만 넣는다 (화면도 `detail.sha === selected`일 때만 그린다).
- 실패는 상세 칸에 보인다.
- 읽기는 async 함수 하나로 단순하게 썼다.

**확인**: 자체 테스트 (`main`), 개발 빌드 훅 `gitDetailDelay`·`gitDetailFail` 사용.
- end-test 상세를 읽은 뒤 graph-live를 고르고 응답을 1.5초 늦춘다. 기다리는 동안 상세 칸에 end-test가 없고, 응답이 오면
  graph-live다.
- 상세 읽기를 실패시키면 상세 칸에 오류가 보이고 이전 상세는 없다.
- 비우기를 끄면 앞의 검사가 실패한다.
- 검사를 쓰다가, 누른 직후에는 이전 상세가 아직 DOM에 남아 있어서 "메시지가 있음"으로 기다리면 바로 넘어가는 것을
  찾았다 (마지막 단계가 계속 "Loading…"을 읽었다. 앱 문제가 아니었다). 기다릴 메시지 내용을 정해 기다리게 고쳤다.

## 3. [P2] 그래프 읽기가 한 번 실패하면 다시 읽지 않음 — 타당, 수정

**검증**: 소스. 지문을 읽기 전에 기억해서, 읽기가 실패해도 다음 확인 때 지문이 같아 다시 읽지 않았다.

**수정**: 지문은 읽기에 성공했을 때만 기억한다(`print`). 읽는 중인 지문(`loading`)은 겹쳐 읽지 않게 따로 두고, 실패하면 둘 다
비운다. 처음 고친 판에서는 `loading`을 비우지 않아 여전히 다시 읽지 않는 빈틈이 있었고, 직접 읽다가 찾아 고쳤다.

**확인**: 자체 테스트 (`main`). 훅 `gitGraphFail`로 첫 읽기만 실패시키면, 다음 확인(3초) 때 다시 읽어 행이 보인다 (읽기 2회).
`loading` 비우기를 끄면 실패한다.

## 4. [P2] 한글 파일 이름이 이스케이프 문자열로 나옴 — 타당, 수정

**수정**: `diff-tree -z --name-status`로 읽는다. 칸마다 NUL로 상태, 이름이 오고, 이름 바꾸기·복사는 옛 이름과 새 이름이 온다.

**확인**: Rust `hostile_messages_names_and_nested_tags`. `한글 파일.txt`, `tab\tname.txt`가 그대로 나온다.

## 5. [P3] 중첩 주석 태그의 칩이 빠짐 — 타당, 수정

**수정**: 참조를 모두 `cat-file --batch-check`에 `<참조>^{commit}`으로 한 번에 넘겨 끝까지 벗긴다. 커밋이 아니면(트리를
가리키는 태그 등) 빼서, `git log` 시작점에도 넣지 않는다.

**확인**: Rust `hostile_messages_names_and_nested_tags`. 주석 태그 `inner`(커밋) ← 주석 태그 `outer`가 모두 그 커밋에 붙고,
트리 태그는 없다.

## 후속 리뷰: 지문 조회 오류가 복구돼도 남음 (P3) — 타당, 수정

**검증**: 소스. 지문 조회가 실패하면 오류를 보이는데, 다음 조회가 성공해도 지문이 같으면 바로 돌아가서 오류를 지우지 않았다.

**수정**: 지문 조회가 성공했고 읽어 둔 그래프의 지문과 같으면 오류를 지운다. 그래프 읽기가 실패한 경우는 지문을 비워 두어서
다음 조회에서 다시 읽고, 읽기가 성공할 때 지운다 (이 경로로 지우지 않는다).

**확인**: 자체 테스트 (`main`). 개발 빌드 훅 `gitFingerprintFail`로 지문 조회를 한 번만 실패시키면, 오류가 보였다가 다음
조회(같은 지문)에서 지워지고 그래프는 그대로다. 지우기를 끄면 실패한다.

- 결과: 타입 검사·빌드 통과, `scripts/selftest.sh` 다섯 시나리오 모두 한 번에 통과.
