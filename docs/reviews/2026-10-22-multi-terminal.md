# 리뷰 대응: 다중 터미널 (2026-10-22)

리뷰 세션이 지적한 내용을 개발 세션이 검증한 기록. 지적을 그대로 받지 않고,
소스·실험으로 타당성을 확인한 뒤 수정했다.

## 1. 탭 바 클릭 후 터미널 포커스 사라짐 (P2) — 타당, 수정

**지적**: 활성 탭을 다시 누르거나 비활성 탭의 ×를 누르면 터미널이 포커스를 잃고 복원되지 않는다.

**검증**
- `Terminal.tsx`의 포커스 효과는 `[focused]`가 바뀔 때만 돈다. 활성 탭 재클릭·다른 탭 × 클릭은
  `focused`를 바꾸지 않으므로 복원 경로가 없다. 코드상 지적이 맞다.
- 브라우저는 포커스할 수 없는 요소에서 mousedown이 일어나면 기본 동작으로 기존 포커스를 해제한다.
- 같은 원인의 경로를 추가로 찾았다: 터미널 둘레 여백(`.pane` 패딩)과 구분선 클릭.

**수정** (`src/Workspace.tsx`)
- 탭 바 전체에서 mousedown 기본 동작을 막는다 (`onMouseDownCapture`, × 버튼의 `stopPropagation`과
  무관하게 동작하도록 capture 단계).
- 활성 탭을 누르면 그 탭의 포커스된 터미널로 포커스를 가져온다 (파일 트리 등에서 돌아올 때).
- 터미널 여백 mousedown → 기본 동작을 막고 그 터미널로 포커스. 구분선 mousedown → 기본 동작 막음.

**확인** (`scripts/selftest.sh`, "포커스:" 항목 8개 통과)
- 한계: 합성 이벤트는 브라우저 기본 동작(포커스 해제)을 실제로 일으키지 않는다. 그래서
  "기본 동작을 막았는가"와 "직접 포커스를 옮겼는가"를 따로 검사했다. 실제 마우스 클릭은 수동 확인 필요.

## 2. WebGL 컨텍스트 손실 미대응 (P2) — 타당, 실제 재현됨, 수정

**지적**: 실행 중 WebGL 컨텍스트를 잃으면 터미널 표시가 멈출 수 있다.

**검증**
- xterm 애드온 소스(`node_modules/@xterm/addon-webgl/lib/addon-webgl.js`): `webglcontextlost`를 받으면
  3초간 복구를 기다리고, 복구되지 않으면 `onContextLoss`만 보낸다. 렌더러 교체는 하지 않는다.
  애드온 README도 `onContextLoss`에서 `dispose()`하라고 안내한다.
- **실험**: 터미널 21개를 열었더니 실제로 11개가 컨텍스트를 잃었다 (나머지 1개는 테스트가 강제로 잃게 함).
  WebKit의 페이지당 WebGL 컨텍스트 수 제한 때문으로 보인다. 즉 "GPU 자원 부족 시"의 가정이 아니라
  탭을 20개 남짓 열면 재현되는 문제다.

| 조건 | WebGL | 기본 렌더러 | 멈춤 |
|---|---|---|---|
| 수정 전 (onContextLoss 처리 없음) | 9 | 0 | **12** |
| 수정 후 | 9 | 12 | 0 |

**수정** (`src/Terminal.tsx`): `webgl.onContextLoss(() => webgl.dispose())` — 기본 DOM 렌더러로 전환.

**확인**: 자체 테스트 "WebGL:" 3개 + "많은 터미널" 통과. 수정을 빼면 같은 테스트가 실패하는 것도 확인.

**후속 검토 거리**: 숨은 탭도 WebGL 컨텍스트를 계속 잡고 있어서, 터미널이 많으면 보이는 터미널이
기본 렌더러(더 느림)로 떨어질 수 있다. 숨은 탭의 WebGL을 해제하는 방식은 필요해지면 검토.

## 3. ⌘W 중복 등록 (리뷰 본문 말미 언급) — 타당, 수정

**지적**: ⌘W가 "터미널 닫기"와 "창 닫기"에 중복 등록되어 있다.

**검증**: Tauri 메뉴 라이브러리 소스 `muda-0.20.0/src/items/predefined.rs:661` — 기본 `close_window`
항목의 단축키가 `CmdOrCtrl+W`로 고정. `menu.rs`에서 이 항목을 "창" 메뉴에 넣고 있었으므로 중복이 맞다.
어느 쪽이 먼저 받는지는 macOS 메뉴 탐색 순서에 기대는 셈이라 보장되지 않는다.

**수정** (`src-tauri/src/menu.rs`): 기본 항목 대신 직접 만든 "창 닫기"를 ⇧⌘W로 둔다 (VS Code와 같은 키).

**확인**: 빌드 통과. 실제 키 입력 확인은 수동으로 필요 (자체 테스트는 메뉴 이벤트를 흉내 낸다).
