# ddak 스펙

VS Code + Claude Code 대신 쓰는, 필요한 기능만 담은 가벼운 개인용 AI 작업 도구.
이름 `ddak` = "딱 필요한 것만". 실행 명령어 이름으로도 쓴다.

이 문서에는 최종 결정과 현재 동작만 둔다. 변천 과정은 git 기록과 `docs/reviews/`에 있다.

## 핵심 개념

```
작업그룹 구성 (앱 전체 설정, 게임의 "파티" 같은 것)
   예: "개발+리뷰" = [claude: 기획/개발], [codex: 리뷰/QA, 읽기 전용]
   └ 기본 구성 1개 지정

프로젝트 목록 (사이드바)
 └ 프로젝트 (폴더)
    ├─ 저장소 1~N개 (server, app, web, docs …)
    ├─ 작업그룹 1 "원본": 원본 폴더에서 작업      ← 탭 1
    │    ├─ claude 세션                          ← 탭 안 분할 창
    │    └─ codex 세션
    ├─ 작업그룹 2: 새 worktree 세트에서 작업       ← 탭 2
    └─ 채팅방 1개 (모든 작업그룹의 세션 + 사용자)
```

- **작업그룹 구성**: 세션 구성 여러 개의 묶음. 하나를 기본으로 지정한다.
- **세션 구성**: 이름(역할) + 실행 명령 + 인자. ddak은 CLI를 해석하지 않는다.
  읽기 전용·페르소나·첫 지시문은 각 CLI의 인자로 표현한다 (새 CLI가 와도 코드 수정 불필요).
- **프로젝트**: ddak에 등록한 폴더. **저장소**: 그 안의 git 저장소 (`.git`이 있는 폴더, 서브모듈 포함).
- **작업그룹**: 프로젝트 안에서 실제로 돌아가는 구성 하나. **탭 하나 = 작업그룹 하나, 분할 창 하나 = 세션 하나**.
  - 첫 작업그룹은 "원본": 원본 폴더에서 바로 작업. 닫아도 아무것도 지우지 않는다.
  - 작업그룹을 추가하면 새 worktree 세트를 만든다.
- 세션마다 다른 모델을 쓸 수 있다. 서브 에이전트는 각 CLI가 알아서 쓰고 ddak은 관여하지 않는다.
- **채팅방**: 프로젝트마다 하나. 모든 작업그룹의 세션과 사용자가 참여. 참여자 이름은 `그룹/역할`.

## 작업그룹 · worktree

```
~/.ddak/worktrees/<프로젝트 이름>-<경로 해시 6자리>/<그룹 id>-<번호>/
   ├─ server/   ← server 저장소 worktree (브랜치 ddak/<이름>, 원본의 현재 커밋에서 시작)
   ├─ web/      ← web 저장소 worktree
   └─ CLAUDE.md, AGENTS.md …  ← 프로젝트 루트의 저장소 아닌 항목은 원본으로 심볼릭 링크
```

- worktree는 ddak이 직접 만든다 (Orca 방식). Claude Code의 worktree 훅은 쓰지 않는다
  (실험: `docs/reviews/2026-10-24-claude-worktree-hook.md`).
- 세션의 작업 폴더는 묶음 폴더다 (claude는 작업 폴더와 상위의 CLAUDE.md를, codex는 AGENTS.md를 읽는다).
- 프로젝트 폴더 밖에 둔다. `DDAK_HOME`으로 `~/.ddak`을 바꿀 수 있다 (자체 테스트용).
- 프로젝트 폴더 자체가 저장소면 그 폴더 전체를 worktree 하나로 만든다.
- 프로젝트 맨 위의 저장소 아닌 항목(`CLAUDE.md`, 메모 등)은 원본으로 링크한다 (작업그룹끼리 공유). 복제하지 않으므로
  작업그룹을 끝내도 그 안의 수정이 사라지지 않는다.
- 브랜치는 `git update-ref refs/heads/<브랜치> <커밋> ""`로 없을 때만 만들고 `git worktree add <폴더> <브랜치>`.
  같은 저장소가 프로젝트에 둘 있으면 두 번째에 항목 이름을 붙인다 (`ddak/<이름>-web`). 이름은 git 규칙에 맞추고 겹치면 `-2`.
- 중간에 실패하면 이번에 만든 것만 지운다 (브랜치는 아직 우리가 만든 커밋을 가리킬 때만 `update-ref -d`).
- 기본은 모든 저장소에 worktree를 만든다. 만들 때 저장소 고르기는 아직 없다.
- 파일 트리는 보고 있는 탭(작업그룹)의 폴더를 보여 주고, 프로젝트 행에 작업그룹 이름을 표시한다.
- 같은 작업그룹에 쓰기 가능한 세션을 둘 이상 두려 하면 경고한다 (세션 추가). 병렬 작업은 그룹 추가로 유도한다.
- 프로젝트 등록·작업그룹 상태는 앱 데이터에 저장한다. 프로젝트 폴더에 표시 파일을 두지 않는다.
- 나중에 저장소를 추가하면 기존 작업그룹에도 worktree를 만들지 묻는다.
- 새 worktree 폴더마다 claude·codex가 처음 한 번 폴더 신뢰를 묻는다. claude의 대화 기록·메모리는 폴더 경로별로 쌓인다.

### 작업그룹 준비

순서: 저장소별 시작 커밋 고정 → worktree 세트 → 가져오기(복제·복사·새로 만들기) → 설치 명령 → 준비 스크립트 →
준비가 성공한 뒤 CLI 시작.
시작점은 원본의 현재 커밋이다 (커밋하지 않은 변경은 들어가지 않는다고 준비 창에 밝힌다). 원본 그룹에는 하지 않는다.

- **설정** (프로젝트마다, 앱 데이터): `setup/<프로젝트 이름>-<경로 해시>.json`
  (`{"clone": [프로젝트 기준 상대 경로…], "install": [{"dir", "command"}…]}`)과 `.sh` (준비 스크립트).
  프로젝트 오른쪽 클릭 → "작업그룹 준비…" 창에서 가져올 항목과 설치 명령을 고르고 스크립트를 연다
  (없으면 안내 주석만 써 두고 `open -t`). 스크립트 파일이 없거나 명령(주석·빈 줄이 아닌 줄)이 없으면 스크립트 없음.
  읽지 못하면 (디렉터리, 권한 등) 그대로 돌려 sh가 오류로 실패하게 한다. 설정 JSON이 잘못되면 작업그룹을 만들지 않는다.
- **가져올 후보**: 저장소마다 git이 무시하는 항목(`ls-files --others --ignored --directory`) 중
  - `node_modules`(옆에 `package.json`): 복제 (아래 조건)
  - cargo `target`(`CACHEDIR.TAG`): 빌드 캐시로 복제
  - 파이썬 가상 환경(`pyvenv.cfg`가 든 폴더): 복제하지 않고 `pyvenv.cfg`의 `home`에 있는 같은 Python으로 `-m venv` 새로 만들기
    (`include-system-site-packages`도 따름). 만드는 곳에 경로가 박혀 다른 곳에 만들어 옮길 수 없어서, 폴더를 직접 만들어
    식별자(dev·inode·만든 시각)를 진행 기록에 적고 그 안에 만든다. 실패하면 바로 지운다. 다시 할 때 폴더가 있으면:
    마친 것은 그대로, 적은 식별자와 같으면(끊긴 우리 것) 지우고 다시 만들기, 우리가 만들지 않은 것은 지우지 않고
    완성된 환경(`pyvenv.cfg`·`bin/python`)이면 그대로 쓰고 아니면 지우라고 알리고 멈춘다.
  - 비밀 파일(`.env`, `.env.*`(예시 파일 제외), `.npmrc`, `.pypirc`, `*.pem`, `*.key`, `credentials.json`, `secrets.json`):
    그대로 복사. ddak 폴더의 0600 임시 파일에 다 쓴 뒤 원본 권한으로 하고 `RENAME_EXCL`로 옮긴다 (실패해도 반쪽·넓은 권한
    파일이 남지 않음, 있으면 덮어쓰지 않음). 링크는 복사하지 않는다.
  - 쓸 자리의 부모를 실제로 따라간 곳이 그 worktree 밖이거나 그 자리가 링크면 아무것도 쓰지 않는다 (원본에서는 일반
    폴더라도 worktree에서는 밖을 가리키는 링크일 수 있다).
  - dist·알 수 없는 캐시·DB·로그는 후보로 내지 않는다.
  아무것도 기본으로 고르지 않는다. 고른 것만 가져오고 자동으로 늘리지 않는다. 저장돼 있지만 지금 없는 항목도 보여서 뺄 수 있다.
- **설치 명령 제안**: 저장소에 커밋된 lockfile에서 (새 worktree에는 커밋된 파일만 있다). `package-lock.json`·
  `npm-shrinkwrap.json` → `npm ci`, `yarn.lock` → `yarn install --frozen-lockfile` (`.yarnrc.yml`이 있으면 `--immutable`),
  `pnpm-lock.yaml` → `pnpm install --frozen-lockfile`, `bun.lock(b)` → `bun install --frozen-lockfile`, `uv.lock` →
  `uv sync --frozen`, `poetry.lock` → `poetry install`, `Pipfile.lock` → `pipenv sync`, `requirements.txt` → 같은 폴더에
  가상 환경 후보가 있을 때만 `<가상 환경>/bin/pip install -r requirements.txt`, `Gemfile.lock` → `bundle install`,
  `go.sum` → `go mod download`. 고른 명령만 가져오기 뒤에 그 폴더에서 `/bin/sh -c`로 돈다.
  제안 명령에 넣는 경로는 셸 인용한다. 설치 폴더를 실제로 따라간 곳이 worktree 밖이면 돌리지 않는다.
  Node 설치(npm·yarn·pnpm·bun)는 그 폴더의 `node_modules`가 우리 복제나 그 설치의 성공으로 생긴 것일 때만 건너뛴다
  (복제한 것을 `npm ci`가 지우지 않게). 실패한 설치가 남긴 `node_modules`면 다시 돌린다. 설치를 돌리기 전에 그 설치의 성공
  기록과 그 `node_modules`의 복제 기록을 지우고, 성공한 뒤에만 다시 적는다.
- **진행 기록**: 작업그룹마다 ddak 폴더의 `.ddak-state-<작업그룹>.json` (`started`·`done`: 복제·가상 환경·설치, `made`: 직접 만든
  폴더의 식별자). 폴더가 있다는
  것만으로는 성공과 실패하고 남은 것을 구분할 수 없어서 쓴다. 작업그룹을 끝낼 때 같이 지운다.
- **조건** (만들 때마다 다시 본다): `node_modules`는 그 폴더부터 저장소 맨 위까지 모든 폴더의 `package.json`과
  lockfile들(npm·yarn·pnpm·bun, `pnpm-workspace.yaml`)이 원본과 새 작업그룹에서 같을 때만 복제하고 (workspace 하위 패키지는
  위쪽 lockfile을 쓴다), 다르면 그 파일 경로와 함께 건너뛰고 알린다 (실패 아님). `target`은 조건 없이 캐시로 복제.
- **복제** (`clone.rs`): 파일마다 `clonefile`로 임시 폴더에 만들고 `renamex_np(RENAME_EXCL)`로 옮긴다. 디렉터리 통째
  clone은 쓰지 않는다. 임시 폴더는 ddak 폴더(`~/.ddak/worktrees/<프로젝트>/`)에 실행마다 `.ddak-clone-<PID>-<번호>`로 만들고,
  끊긴 실행의 것은 그 PID가 끝났을 때만 지운다. 파일·폴더의 수정 시각과 권한을 유지한다 (폴더는 안을 채운 뒤 되돌린다).
  이미 있으면 그대로 둔다. 상대 링크는 운영체제가 따라간 실제 위치(`canonicalize`, 글자로 계산하지 않음)가 원본에서는
  원본 저장소 안일 때만 만든다. 새 worktree 쪽도 옮기기 전에 본다: 링크가 놓일 자리에서 운영체제처럼 한 단계씩
  따라가되 아직 없는 복제 부분은 임시 폴더에서 읽고 (`resolve_at`), 밖이면 지운다. 그 뒤 폴더 시각·권한을 되돌리고
  옮긴다 (맨 위 폴더의 권한만 옮긴 뒤에). 제자리에는 확인을 마친 것만 나타난다.
  절대 링크·밖을 가리키는 링크·가리키는 것이 없는 링크·소켓·FIFO·장치는 빼고 알린다.
  다른 볼륨이라 clone이 안 되면 실제 복사로 대신하지 않고 실패한다.
- **실행** (`prepare.rs`): 할 준비(가져올 항목, 설치 명령, 스크립트)가 있으면 세션 아래 "setup" 창에서 이 앱 실행 파일을
  도우미로 돌린다 (`ddak --ddak-setup <원본> <작업그룹 폴더> <이름> <스크립트> <할 일 JSON>`, `main.rs`가 창을 열기 전에 분기).
  도우미가 가져오고 설치한 뒤 `DDAK_ORIGIN`·`DDAK_GROUP`을 넣어 `/bin/sh <스크립트>`로 exec한다. 하나라도 실패하면
  그 뒤는 하지 않고 1로 끝난다. 도우미 출력은 영어 진단 문구다.
  - 끝나도 셸을 띄우지 않아(`pty_spawn`의 `shellAfter: false`) 종료 코드를 받는다. 창은 출력을 볼 수 있게 남는다 (⌘W로 닫기).
  - 세션(CLI) 창은 준비가 성공할 때까지 터미널 대신 "준비가 끝나면 시작" 안내를 보이고, 포커스는 준비 창.
    성공하면 세션을 띄우고 포커스를 첫 세션으로 옮긴다.
  - 실패(종료 코드), 중단(돌던 준비 창을 닫음·시그널), 준비 창을 띄우지 못함(작업 폴더 없음 등)이면
    세션 창에 "다시 준비 / 그래도 시작".
    다시 준비는 새 터미널에서 다시 돌린다 (창을 닫았으면 다시 연다). 그래도 시작은 이번만 세션을 띄우고,
    실패 표시(준비 창 표시, 탭의 `!`)는 남는다.

### 복원

- 프로젝트마다 마지막 작업 화면을 앱 데이터의 `workspaces/<프로젝트 이름>-<경로 해시>.json`에 둔다 (`workspace.rs`,
  내용은 프론트 `workspaceState.ts`가 정한다). 탭(순서·활성·분할과 비율·포커스·폴더·그룹·작업그룹·이름), 창마다의 세션,
  준비 상태. 터미널 제목·출력은 두지 않는다. 바뀌면 바로 쓴다 (구분선 끌기만 0.3초 모음). 옆에 쓰고 옮긴다.
- 읽기·치우기·저장은 프로젝트마다 한 줄로 선다 (Workspace 인스턴스와 상관없이). 그래서 앞 저장이 끝난 뒤에 다음을
  보내고, Workspace가 다시 생기면(StrictMode, 목록에서 뺐다 넣음) 이전 인스턴스의 남은 저장이 끝난 뒤에 읽는다.
  정리된 Workspace는 읽기 뒤에 파일을 치우거나 알리거나 상태를 바꾸지 않는다.
- 종료 때 따로 저장을 마치는 장치는 없다. 저장 요청이나 줄이 끝나기 전에 앱이 끝나면 그 변화(구분선 끌기는 0.3초 모으는
  동안의 변화까지)를 잃을 수 있다.
- 프로젝트 Workspace를 처음 만들 때(앱을 켜면 활성 프로젝트, 다른 프로젝트는 처음 열 때) 읽어서 되살린다. 없으면
  기본 작업그룹으로 연다. 내용이 깨졌거나(UTF-8·JSON이 아님) 모양이 틀리면 `.json.bad`로 치워 두고 기본으로 연다.
  읽지 못하면(권한 등) 기본으로 열되 알리고, 앱을 다시 켤 때까지 그 프로젝트는 저장하지 않는다 (덮어쓰지 않게).
  읽기 전에는 아무것도 띄우지 않고 단축키·새 작업그룹도 무시한다. 창·탭 번호가 겹치면(같은 탭 안 포함) 모양이 틀린 것.
- 세션은 이어서 하기로 띄운다: 저장한 세션 구성의 `resume` 인자 (없으면 처음 인자). 저장한 구성을 그대로 쓰므로
  `groups.json`에 `resume`을 더해도 그 뒤에 만든 탭부터 적용된다. 인자의 `{session}`은 창마다 정한 UUID (처음과 복원 때
  같은 값). 이어서 하기가 0이 아닌 코드로 끝나면 터미널에서 새로 시작할지 묻고(`[y/N]`) y일 때만 처음 인자로
  (시작 실패와 쓰다가 끝난 것을 구분할 수 없어서 자동으로 새로 시작하지 않는다).
  준비를 기다리던 탭의 세션은 뜬 적이 없어서 처음 인자로.
- 한계: codex는 시작할 때 세션 ID·이름을 정할 수 없어서 기본 설정은 `resume --last`(그 폴더의 가장 최근 대화)로 이어 간다.
  같은 폴더에서 다른 codex(ddak 밖에서 띄운 것 포함)를 쓰면 다른 대화를 이어 갈 수 있다.
- 셸 창은 같은 폴더에서 새 셸. 준비 창은 되살리지 않는다. 준비를 마치기 전에 닫혔으면 중단으로 보고 세션 창에
  다시 준비 / 그래도 시작.
- 목록에서 뺀 프로젝트의 상태도 남겨 둔다 (다시 추가하면 마지막 상태로 연다).

### 그룹 끝내기

- 작업그룹 탭 오른쪽 클릭 → "작업그룹 끝내기…" (새 worktree로 만든 작업그룹에만). 탭을 닫기만 하면 worktree는 남는다.
- 창이 저장소마다 다음을 보인다. 병합·PR은 사용자(또는 에이전트)가 한다.
  - 브랜치
  - 커밋하지 않은 변경 수 (추적 안 하는 파일 포함, 무시된 파일 제외)
  - 어느 브랜치에도·원본 HEAD에도 없는 커밋 수 (worktree HEAD 기준, detached HEAD에서 만든 것 등)
  - 원본의 지금 HEAD에 병합 안 된 커밋 수. 병합 판단은 원본의 지금 HEAD 기준이다 (원격 병합·squash 병합과는 다르다).
- 지우는 기능이라 아는 것만 지운다. 다음 중 하나라도 있으면 아무것도 지우지 않고 멈춘다.
  - 커밋하지 않은 변경
  - 브랜치에 없는 커밋
  - 작업그룹 폴더에 끝낼 worktree, 우리가 만든 링크(원본의 같은 이름 항목을 가리킴), `.DS_Store` 말고 다른 항목
  - 자리는 있는데 온전하지 않은 worktree (`.git` 없음)
  - 상태를 확인하지 못함 (git 오류. 원본 HEAD에 아직 커밋이 없는 경우 등)
- 창에 "지우기 전에 세션을 먼저 닫으며, 진행 중인 응답은 끊길 수 있음"을 적는다.
- 순서 (`group_end` 한 번):
  1. 확인한다. 끝낼 수 없으면 세션을 건드리지 않는다.
  2. 끝날 때까지 이 폴더(와 그 안)를 잠근다. 그동안 그 안에는 새 터미널을 띄우지 않는다.
  3. ddak이 이 폴더에서 띄운 터미널(닫는 중인 것 포함)을 모두 끝내고 기다린다 (터미널 닫기와 같은 방식). 끝내는 동안
     창은 닫지 않는다.
  4. 다시 확인하고 지운다. worktree는 `git worktree remove`(강제 없음)로 지운다. 마지막에는 우리가 만든 링크만 지우고, 빈
     폴더만 지운다.
- 세션을 끝낸 뒤 확인이나 지우기가 실패하면, 그 폴더의 탭은 남고 세션을 이어서 하기로 다시 띄운다.
- ddak 밖에서 띄운 프로세스와 터미널 세션을 떠난 프로세스(스스로 setsid한 데몬 등)는 막지 못한다.
- 브랜치는 작업그룹을 만들 때 적은 것(`.ddak-group-<이름>.json`: 저장소, worktree, 브랜치, 시작 커밋)만 지운다.
  - 지금 커밋이 원본 HEAD에 있고, 쓰는 곳이 없으면 지운다. 쓰는 곳은 어느 worktree(원본 포함)의 HEAD, 진행 중인 rebase·bisect다.
    그 상태 파일을 읽지 못하면 (권한 등) 쓰는지 모르므로 남긴다.
  - 지우는 것은 그 커밋일 때만이다 (`update-ref -d`의 기대값). `git branch -d`는 upstream이 있으면 upstream 기준이라 쓰지 않는다.
  - 남긴 브랜치는 이유(병합 안 됨, 쓰는 중, 쓰는지 확인하지 못함, 끝내는 중에 바뀜, 기록 없음)와 함께 알린다.
  - 검사와 지우기 사이에 누가 그 브랜치를 체크아웃하면, 그 worktree는 없는 브랜치에 남는다 (지운 커밋은 원본 HEAD에 있다).
  - worktree 안에서 사용자가 바꾼 다른 브랜치는 지우지 않는다.
  - 기록이 없는 작업그룹(이전 버전)의 브랜치는 모두 남긴다. 저장소는 지금 프로젝트 모양으로 짐작한다 (짐작에서 빠진
    worktree는 모르는 항목으로 걸린다).
- 끝나면 그 폴더의 탭을 닫고, 만든 기록·진행 기록을 지운다.
- 중간에 실패하면 이미 지운 것은 그대로다. 탭이 남아 다시 끝내기를 누르면 이어서 정리한다.

## 기능 범위

1차 (필수)
1. **프로젝트 목록 + 파일 트리** — VS Code 수준의 파일 탐색. 프로젝트·저장소·worktree를 아이콘으로 구별.
2. **다중 터미널** — 탭 + 탭 안 분할.
3. **작업그룹** — 구성대로 세션을 띄운다. 추가 그룹은 worktree 세트 + 준비.
4. **프로젝트 채팅방** — 세션 간 / 메인 에이전트 간 / 사용자와의 대화.
5. **git graph** — 커밋 그래프. 어떤 세션이 어떤 브랜치에서 작업 중인지 표시.

나중에 (필요할 때 하나씩)
- 마크다운 뷰어, diff 뷰어
- 환경설정 (설정 화면 또는 파일, 터미널 글꼴 등). 그때 localStorage의 테마·언어·배율도 옮긴다.

## 세션 실행 방식

기존 CLI(claude, codex, gemini 등)를 터미널(PTY)에서 그대로 실행한다. ddak은 터미널·worktree·채팅방만 제공하고
에이전트 기능은 각 CLI에 맡긴다 (구독 요금제 그대로, CLI 업데이트를 바로 누림).
깨우기가 불편해지면 특정 CLI만 헤드리스(`claude -p --output-format stream-json`) + 자체 UI로 바꾸는 것을 검토한다.

## 기술 스택

Tauri 2 + React(TypeScript) + Rust. Electron은 쓰지 않는다 (무거움). 터미널은 xterm.js (VS Code와 같음).

| 기능 | 구현 |
|---|---|
| 파일 트리 | 웹 UI + Rust `notify` |
| 터미널 | xterm.js 6 + Rust `portable-pty` |
| worktree | `git` CLI 호출 |
| git graph | Rust `gix`로 커밋/레인 계산 → SVG/Canvas + 가상 스크롤 |
| 채팅방 | 앱 내장 MCP 서버 (127.0.0.1, `tiny_http`) + JSONL 파일 |

- Vite는 6으로 고정 (이 맥의 Node 20.10에서 Vite 7+가 돌지 않는다. Node를 올리면 Vite도 올려도 된다).

## 현재 동작

### 터미널

- PTY 출력은 바이트 그대로(Channel + Raw) 프론트로 보낸다 (문자열로 바꾸면 한글이 경계에서 깨진다).
- PTY에 `IUTF8`을 켠다 (`pty.rs`). 끄면 tty 줄 편집(read, 비밀번호 입력 등)에서 한글을 지울 때 1바이트만 지운다.
- 셸이 exit 하면 그 터미널이 닫힌다. 탭의 마지막 터미널이 닫히면 탭도 닫힌다.
- 종료(코드)는 출력과 같은 채널로 마지막에 온다 (`{"exit": 코드}`). 자식이 끝난 뒤 출력이 끝나기를 최대 0.5초 기다린다.
- 터미널을 닫으면 그 터미널의 세션(자식이 setsid로 만든 것) 전체를 끝낸다. 대화형 셸이 작업마다 따로 만든 그룹과
  nohup으로 띄운 작업도 포함한다.
  - 세션의 프로세스에 SIGHUP과 SIGCONT를 보낸다. 0.25초 뒤에도 남으면 SIGKILL을 보낸다.
  - 좀비를 뺀 구성원이 없어지면 자식을 거둔다. 3초 안에 다 끝나지 않으면 거두지 않고 "닫는 중"으로 남는다.
  - 거두기는 이 끝내기만 한다. 끝난 자식은 그때까지 좀비로 PID(세션 ID)를 쥐고 있어서, 신호가 다시 쓰인 PID나 세션으로
    가지 않는다.
  - 스스로 setsid해 세션을 떠난 프로세스는 찾지 못한다.
  - 종료 코드는 `waitid WNOWAIT`의 siginfo에서 읽는다.
- 터미널마다 띄운 폴더(실제 경로)를 기록한다. 닫았지만 아직 다 끝나지 않은 터미널은 다 끝날 때까지 따로 추적한다
  (작업그룹 끝내기가 기다린다).
- 작업 폴더가 없으면 띄우지 않는다 (portable-pty는 없는 폴더면 홈 폴더에서 띄운다).
- WebGL 렌더러. 컨텍스트를 잃으면 DOM 렌더러로 바꾼다 (터미널 20개 남짓에서 실제로 잃는다).
- 한글 입력 (`src/hangul.ts`): macOS WebKit은 composition 이벤트 없이 `insertText` → `insertReplacementText`로 보낸다.
  입력기 글자는 xterm에 넘기지 않고 직접 보낸다 (바꾸기 = 바뀐 코드 포인트 수만큼 DEL + 새 글자).
  xterm이 이미 보낸 키는 건너뛰고(`onKey`로 셈), keyCode 229 keydown은 xterm에 넘기지 않는다.
  composition 이벤트를 쓰는 입력기는 xterm에 맡긴다. 입력 전송은 줄 세운다 (invoke 순서가 보장되지 않는다).
- 키 (`Terminal.tsx`의 `terminalKey`): ⌘⌫ → Ctrl+U, ⇧↩ → 세션 구성의 `shiftEnter` (기본 claude·codex는 ESC CR).
  xterm의 키 처리 함수는 하나만 걸 수 있어 한글 보정과 합쳐 둔다.
- 배율: WKWebView는 배율에 devicePixelRatio를 바꾸지 않아서 `src/zoom.ts`가 (실제 값 × 배율)을 돌려준다.
  `.xterm-viewport` 배경은 `--terminal-bg`로 덮는다 (`xterm.css`가 `#000`으로 고정).

### 탭 · 분할 · 단축키

- 탭 하나 = 분할 트리 하나 (`src/layout.ts`). 터미널은 탭 안에서 모두 형제로 두고 위치만 바꾼다 (다시 마운트되면
  셸이 죽는다). 숨은 탭은 `display: none`. 창을 다른 탭으로 옮기면 PTY가 죽으므로 옮기기는 없다.
- 단축키 (네이티브 메뉴, `menu.rs`): ⌘T 원본 폴더의 셸 탭, ⇧⌘T 새 작업그룹, (세션 추가는 단축키 없음), ⌘D 오른쪽 분할, ⇧⌘D 아래 분할,
  ⌘W 터미널 닫기, ⇧⌘W 창 닫기. ⌘1~9 / ⇧⌘[ ] 탭 이동 (프론트 keydown). ⌘G는 macOS "다음 찾기"라 쓰지 않는다.
- 탭 바: 버튼은 아이콘(새 터미널, 새 작업그룹, 분할 둘, 채팅). 탭 영역만 가로 스크롤 (스크롤바 숨김), 버튼은 고정.
  활성 탭이 바뀌거나 탭 너비가 바뀌면 활성 탭이 보이게 맞추되, 휠로 넘겨 둔 동안은 끌어오지 않는다
  (휠 여부는 wheel 뒤의 scroll로만 판단, 위치는 `getBoundingClientRect`로 재고 올림).
- 탭 이름 바꾸기: 더블클릭 또는 오른쪽 클릭. Enter·다른 곳 클릭 확정, Esc 취소, 비우면 원래 제목. 탭 제목만 바뀐다.
- 탭 순서: 4px 넘게 끌면 포인터가 지나간 자리로 옮긴다. 끝에 가면 그쪽으로 스크롤. 끌기는 pointerup·pointercancel·
  버튼 뗌·언마운트에서 정리한다 (탭 끌기와 구분선 끌기가 `trackPointer` 하나).
- 탭이 없을 때: 탭 바는 그대로(분할 버튼만 비활성), 가운데에 "프로젝트 폴더에서 <기본 그룹> 열기", 새 작업그룹,
  새 터미널. 그룹 설정을 못 읽었으면 첫 버튼은 없다.
- 작업그룹 세션 창 위에 역할 이름과 "읽기 전용" 표시. 탭마다 폴더(cwd)가 있고 그 탭의 분할 창도 그 폴더에서 열린다.

### 사이드바 · 파일 트리

- 사이드바 = 프로젝트 목록. 펼치면 그 폴더의 파일 트리. 저장소(`.git` 폴더)·worktree(`.git` 파일) 아이콘.
  펼치기 화살표는 SVG 꺾쇠, 펼치면 90° 회전.
- 링크는 이름 뒤 ↗, 마우스를 올리면 가리키는 경로. 폴더가 사라진 프로젝트는 취소선, 열지 않는다 (빼기만 가능).
- 트리 루트가 바뀌면 이전 항목·입력란·오른쪽 클릭 메뉴를 바로 버린다 (`<Children key={루트}>`).
- 자동 갱신: 펼쳐진 폴더만 하위 제외로 감시 (`watch.rs`, FSEvents). 이벤트의 실제 경로를 트리 경로로 바꾼다.
- 오른쪽 클릭 메뉴는 화면 안에 그린다 (`ContextMenu.tsx`, 자체 테스트가 누를 수 있게).
  새 파일·새 폴더·이름 바꾸기는 VS Code처럼 그 자리 입력란 (`useNameInput`). Enter 확정, Esc·다른 곳 클릭 취소.
  이름 검사는 `fs.rs`의 `child_path` (빈 이름, `/`, `.`, `..`, 이미 있음). 중간 폴더 만들기·삭제는 없다.
- 이름 바꾸기는 같은 폴더 안에서 `renamex_np(RENAME_EXCL)` (덮어쓰지 않음, 대소문자만 바꾸기도 됨).
  파일은 확장자 앞까지 선택.

### 프로젝트 · 저장소

- 목록은 앱 데이터의 `projects.json` (`projects.rs`). 프론트가 내용을 정하고 Rust는 읽고 쓰기만 한다.
  파일을 못 읽으면 저장하지 않는다 (빈 목록으로 덮어쓰지 않게). `DDAK_DATA_DIR`로 앱 데이터 폴더를 바꾼다.
- 프로젝트마다 Workspace(탭·분할)가 따로 있다. 처음 열 때 만들고 다른 프로젝트로 가면 숨기기만 한다 (셸 유지).
  단축키는 보이는 프로젝트만 받는다. 열린 프로젝트를 빼면 확인 후 터미널을 닫는다.
- 저장소 추가 (프로젝트 행 `+`, `repos.rs`): URL에서 clone, 또는 로컬 저장소 연결(프로젝트 안에 심볼릭 링크).
  옮기기는 두지 않는다. clone은 묻지 않고 실패하게 한다 (`GIT_TERMINAL_PROMPT=0`, ssh `BatchMode=yes`). 취소는 없다.

### 작업그룹 구성 · 실행

- 앱 데이터의 `groups.json` (`groups.rs`): `{ default, groups: [{ id, name, sessions: [{ name, command, args, resume, readOnly, shiftEnter }] }] }`.
  없으면 기본 설정을 `create_new`로 써 둔다. 모르는 키는 오류. 편집은 앱 메뉴 "작업그룹 설정…"(`open -t`).
  파일이 바뀌면 다시 읽고(마지막 요청만 적용), 잘못되면 사이드바에 오류를 보이고 마지막으로 올바르던 설정을 쓴다.
- 기본 설정: `dev-review` = claude(`--session-id {session}`, `--append-system-prompt`로 역할, 복원은 `--resume {session}`)
  + codex(`-s read-only`, `-c developer_instructions="…"`, readOnly, 복원은 `resume --last`와 같은 옵션), `shell` = 셸 하나.
- 세션 실행: `$SHELL -l -i -c '<명령과 인자>; exec $SHELL -l'` (인자는 작은따옴표). CLI가 끝나면 셸이 남는다.
  `command`가 비면 그냥 셸.
- 프로젝트를 처음 열면 첫 탭 = 기본 작업그룹 (세션을 같은 폭으로 나란히). 설정을 못 읽었으면 셸 하나.
- 세션 추가 (Terminal 메뉴 "세션 추가…", 탭 오른쪽 클릭. 단축키 없음, `AddSessionDialog.tsx`):
  - 창에 설정의 모든 그룹의 세션을 보인다 (이름, 그룹, 읽기 전용, 명령).
  - 하나를 고르면 그 탭의 포커스된 창 오른쪽에 분할 창으로, 그 탭의 폴더에서 띄운다. 창마다 새 세션 ID를 쓴다. 준비를
    기다리는 탭이면 다른 세션처럼 준비가 끝난 뒤에 뜬다.
  - 쓰기 가능한 세션은 명령이 있고 읽기 전용이 아닌 것이다 (그냥 셸과 준비 창은 세지 않는다).
  - 탭에 쓰기 가능한 세션이 이미 있는데 쓰기 가능한 세션을 또 고르면 경고한다: 취소 / 새 작업그룹 / 그래도 추가.
    읽기 전용은 경고하지 않는다.
  - 설정 파일 자체에 쓰기 가능한 세션이 둘 있는 그룹은 사용자가 정한 것이라 경고하지 않는다.

- 기본 언어 영어. 사전은 `src/i18n/` (`en.ts` 기준, 다른 언어는 `Messages` 타입). 네이티브 메뉴 문구도 같은 사전에서

### 자체 테스트

- `scripts/selftest.sh`가 시나리오(`main`, `restart`, `corrupt`, `resume-save`→`resume-check`)마다 앱 데이터 폴더를 따로
  두고 앱을 띄운다 (resume 둘은 같은 폴더를 써서 저장한 상태를 다음 실행이 복원). `SELFTEST_SCENARIOS="main resume"`처럼
  일부만 돌릴 수 있다.
  진짜 claude·codex를 띄우지 않도록 테스트용 `groups.json`을 넣는다.
- 탭 스크롤 검사는 탭 15개로 WebGL 컨텍스트를 밀어내므로 WebGL·배율 검사 뒤에 둔다.
- 터미널에 보내는 명령(`run`)은 900바이트 이하. 셸이 줄 편집으로 돌아오기 전에 친 입력은 tty가 한 줄에 1024바이트
  (`MAX_CANON`)까지만 받고 나머지를 버린다. 넘으면 `run`이 바로 실패로 알린다.
- 앱 창이 포커스를 잃으면 WebKit이 화면 갱신을 늦춘다. 화면에 묶인 확인은 고정 대기 대신 조건을 기다리고,
  실패하면 focus·rAF 지연을 기록한다.
- 직접 확인이 필요한 것: 실제 키 입력의 메뉴 단축키(⌘W, ⌘+), ⌘C/⌘V, codex의 Alt+Enter.
  터미널 입력 처리를 바꾼 뒤에는 dev 앱을 새로 띄워 확인한다 (HMR로 떠 있던 터미널에는 반영이 불확실).

## 배포 계획 (나중에 하나의 단계로)

- 공개 GitHub 저장소(madsys11/ddak). 사용자가 먼저 쓰고 이후 팀원(모두 macOS)에게 배포한다.

- `tauri-plugin-updater` + GitHub Actions(`tauri-action`) + GitHub Releases(`latest.json`).
  태그 push → 빌드·서명·공증 → 릴리스 → 앱이 업데이트 확인 후 설치.
- 업데이트 서명 개인 키는 GitHub Secrets + 별도 백업 (잃으면 기존 설치본에 업데이트 불가).
- Developer ID 서명 + 공증. 준비물: Developer ID Application 인증서(조직 계정이면 Account Holder만 발급),
  공증용 앱 암호 또는 App Store Connect API 키 → GitHub Secrets.
- 앱 식별자 `dev.ddak.desktop`은 임시값. 배포 전에 확정한다 (배포 뒤에는 바꾸기 어렵다).
- 라이선스는 팀 배포 전에 정한다. 버전 번호(`package.json`, `Cargo.toml`, `tauri.conf.json`)는 배포 단계에서 한 곳으로.

## 채팅방 설계

모델 종류와 무관하게 참여시키기 위해 MCP를 쓴다 (Claude Code, Codex CLI, Gemini CLI 모두 지원). `src-tauri/src/chat.rs`.

```
ddak 앱
 ├─ MCP 서버 (streamable HTTP, 127.0.0.1의 빈 포트, 앱을 켤 때마다 다르다)
 │    도구: post_message, read_messages, list_members
 ├─ 앱 데이터 chats/<프로젝트 이름>-<경로 해시>.jsonl: 메시지를 한 줄씩 붙인다
 │                                              .names.json: 창(키) → 참여자 이름
 └─ 터미널 세션들 ─ 창마다 다른 주소로 같은 채팅방 접속
```

- 프로젝트마다 방 하나. 참여자는 사용자(`user`)와 ddak이 띄운 작업그룹 세션(명령이 있는 것, 준비 창 제외).
- 참여자 이름은 `작업그룹/역할` (원본 작업그룹은 `origin`). 창마다 고정인 키(창의 세션 ID)에 이름을 정해
  `.names.json`에 둔다. 그 키의 터미널이 모두 닫혀도, 앱을 다시 켜도 그 창은 같은 이름이고, 그 이름은 다른 창에 주지
  않는다 (겹치면 `-2`). 이름 파일을 읽지 못하거나 깨졌으면 그 실행에서는 메모리에만 두고 파일을 덮어쓰지 않는다.
  터미널을 닫으면 참여자에서 빠진다.
- 참여: 세션을 띄울 때 창마다 추측할 수 없는 토큰을 만들고, 인자 안의 `{chat}`을 그 창의 주소
  (`http://127.0.0.1:<포트>/mcp/<토큰>`)로 바꾼다. 서버는 주소로 보낸 사람을 안다. MCP를 붙이는 인자는 설정에 있다
  (ddak은 CLI를 해석하지 않는다).
  - claude: `--mcp-config '{"mcpServers":{"ddak":{"type":"http","url":"{chat}"}}}' --allowedTools mcp__ddak`
  - codex: `-c mcp_servers.ddak.url="{chat}" -c mcp_servers.ddak.default_tools_approval_mode="approve"`
    (없으면 도구마다 승인을 요구한다)
  - 기본 설정에 들어 있다. 예전에 만든 `groups.json`에는 직접 넣는다. 저장된 탭은 저장할 때의 인자를 그대로 쓰므로,
    설정을 고치면 새 작업그룹이나 새로 추가한 세션부터 채팅에 참여한다.
- 서버: JSON-RPC 요청 하나에 JSON 응답 하나 (알림은 202). 서버가 먼저 보내는 GET 스트림은 없다(405).
  모르는 토큰은 404. Host가 127.0.0.1·localhost가 아니거나, Origin이 있는데 이 서버 자신(`http://127.0.0.1:<포트>`,
  `http://localhost:<포트>`)이 아니면 403 (DNS 리바인딩·다른 사이트의 브라우저 요청. CLI는 Origin을 보내지 않는다).
- 메시지: 일반 텍스트, 스레드 없음. `@이름`·`@all`로 멘션한다. 보낼 때 있던 참여자 중 멘션된 사람(보낸 사람 제외,
  `@all`이면 모두)을 받는 사람(`to`)으로 적는다. 모르는 이름은 무시한다.
  - 멘션은 `@` 바로 뒤에 오는 참여자 이름 중 가장 긴 것이다 (뒤가 끝·공백·문장부호일 때). 이름을 공백으로 나누지 않으므로
    공백·문장부호가 든 이름(`origin/코드 리뷰`)도 그대로 멘션한다. 맞춘 이름 안의 `@`는 다시 보지 않는다.
- 파일:
  - 줄마다 따로 읽어 깨진 줄(JSON·UTF-8)만 건너뛴다.
  - 마지막 줄이 줄바꿈 없이 끊겼으면 줄을 바꾼 뒤 붙인다.
  - 번호는 지금 가장 큰 번호 + 1.
  - 파일을 읽지 못하면(없음 말고) 그 방은 읽기·쓰기를 모두 오류로 멈춘다 (번호가 겹치지 않게). 다음에 다시 읽어 본다.
- 도구:
  - `list_members`: 참여자 목록. 자기는 `(you)`.
  - `post_message(text)`: 보낸다. 알림 받는 사람을 돌려준다.
  - `read_messages(since?, limit?)`: since가 없으면 안 읽은 것 (처음이면 마지막 20개). 읽은 위치는 참여(토큰)마다
    메모리에 둔다. 앱이나 그 터미널을 다시 띄우면 처음처럼 마지막 20개부터다.
- 새 메시지는 프론트에 `chat` 이벤트로 알린다 (`{ project, message }`). 프론트 명령: `chat_messages`, `chat_post`(사용자로
  보냄), `chat_members`.
- 깨우기 (`pty.rs` wake): CLI 에이전트는 스스로 채팅방을 확인하지 않으므로, 멘션된 세션의 터미널에 알림 문구를 입력하고
  300ms 뒤에 Enter를 따로 보낸다. 한 번에 보내면 claude가 붙여넣기로 봐서 제출하지 않는다
  (`docs/reviews/2026-10-24-chat-wake-experiment.md`). 멘션 없는 메시지는 기록만 한다.
  - 문구: `[ddak] New chat message from <보낸 사람들>. Read it with the ddak read_messages tool, then reply with
    post_message and @mention whoever should get the reply.` 기다리는 동안 온 메시지의 보낸 사람은 모아서 한 번에 알린다.
  - 입력 중이면 기다린다: 그 창에서 사용자가 마지막으로 친 것이 Enter(제출, ⇧Enter의 ESC CR은 아님)이고 3초 동안 입력이
    없을 때만 깨운다. 한 번도 치지 않은 창은 바로 깨운다. ddak은 CLI 화면을 해석하지 않으므로 사용자가 친 키로만 판단한다.
    사용자 입력은 키·붙여넣기·IME 이벤트 직후(300ms 안)에 나온 데이터 중 터미널 자동 응답 모양이 아닌 것이다
    (`Terminal.tsx` isTerminalReply). 자동 응답은 xterm 6.0이 만드는 것 전부다: CSI [?>]? … c|n|R|t, CSI ? … $y, DCS, OSC,
    포커스. 키보드가 만드는 CSI는 이 끝 글자와 겹치지 않는다 (R로 끝나는 ⇧F3 등은 글자가 아니라 응답으로 봐도 된다).
    xterm이 프로그램의 질의에 보내는 응답과 프로그램 입력은 넣지 않는다.
  - 기다리는 창은 이름표에 "채팅 알림 대기"를 띄우고, 누르면 바로 깨운다 (초안이 있어도).
  - 알림을 쓴 뒤 Enter를 보내기 전에 사용자가 치면 Enter를 보내지 않는다 (사용자가 Enter를 치면 함께 제출된다).
  - 작업 중이어도 보낸다 (claude·codex 모두 이어서 처리했다).
  - 프론트에는 `chat-wake` 이벤트(`{ pty, pending, seq }`)로 알린다. seq는 대기 상태가 바뀔 때마다 잠금 안에서 매기고,
    터미널은 더 오래된 seq를 버린다. 터미널은 이 이벤트의 등록이 끝난 뒤에 띄운다 (등록 전의 상태를 놓치지 않게).
  - 한계: 새 worktree에서 처음 뜬 claude·codex가 폴더 신뢰를 묻는 동안 깨우면, 알림의 Enter가 기본 선택(신뢰)을 고를 수
    있다. 리뷰어처럼 사용자가 직접 치지 않는 세션도 깨우려고 받아들였다.
- 화면 (`ChatPanel.tsx`): 프로젝트마다 오른쪽 패널. 탭 바 오른쪽 끝의 채팅 버튼으로 여닫는다 (단축키 없음, 연 상태는
  저장하지 않는다).
  - 위: 참여자 칩. 누르면 입력란에 `@이름 `을 넣는다.
  - 가운데: 메시지 목록. 보낸 사람, 받는 사람, 시각(앱 언어)을 보인다. 나에게 온 것은 왼쪽 줄로, 내가 보낸 것은 배경으로
    구분한다. 맨 아래를 보고 있으면 새 메시지를 따라 내려간다.
  - 아래: 입력란. Enter로 사용자(`user`)로 보내고, ⇧Enter는 줄바꿈이다. 한글 조합을 확정하는 Enter로는 보내지 않는다.
    보내는 동안 새로 쓴 것은 응답이 와도 남긴다 (보낸 내용 그대로일 때만 비운다).
  - 닫으면 (× 또는 버튼) 그 프로젝트의 선택된 터미널로 포커스를 돌린다.
  - 닫혀 있어도 떠 있으면서 받는다. 닫혀 있는 동안 나를 멘션한 메시지가 오면 채팅 버튼에 점을 찍고, 열면 지운다.
  - Rust 이벤트(`chat`, `chat-members`)를 받으면 다시 읽는다 (이벤트의 프로젝트는 실제 경로라 비교하지 않는다).
    이벤트를 먼저 등록한 뒤 처음 상태를 읽고, 메시지·참여자 모두 마지막 요청의 결과만 쓴다. 등록이 하나라도 실패하면
    성공한 등록도 풀고 "스스로 새로 고치지 못함"을 보인다 (처음 읽기는 한다. 프로젝트를 뺐다 다시 넣으면 다시 시도).

- 자체 테스트 `restart`에서 세션 명령이 끝난 직후 `pwd`가 한 번 시간 초과 (재현 안 됨). 다시 나면 화면을 기록하고
  한 번 더 보낸다.
- 자체 테스트 `resume-check`에서 셸 창의 첫 프롬프트를 15초 안에 못 본 적이 한 번 있다 (재현 안 됨, 다시 두 번 통과).
  다시 나면 `ready`가 남기는 화면 상태를 본다.
- 자체 테스트 `main`의 WebGL 검사에서 `WEBGL_lose_context` 확장을 못 얻은 적이 한 번 있다 (`getExtension`이 null, 재현 안 됨,
  다시 돌려 통과). 다시 나면 그때 터미널 수와 렌더러를 기록한다.
- 자체 테스트 `main`의 "실제로 기록한 빠른 한글 입력 재현"이 가끔 글자를 겹쳐 보낸다 (`[마찬찬가지로]`, `[마찬갖가지로]`).
  2026-10-24 하루에 세 번 났다. 채팅 패널을 넣기 전에도 났고, 다시 돌리면 통과한다. 그때 load average는 5~6이었다.
  부하가 클 때 한글 보정(`src/hangul.ts`)의 타이밍 문제일 수 있어 따로 조사한다.
